- 日期：2026-10-07
- 状态：已生效（护栏在 CI）
- 关联：`haoyue_tests/coverage.runsettings`、`.github/workflows/ci.yml`

| 模块 | 行覆盖 | 说明 |

## 门槛机制

- `haoyue_tests/coverage.runsettings` 对 `[haoyue_runtime*]*` 设 **行覆盖 ≥ 70%** 的硬门槛（ThresholdType=line, ThresholdStat=total）；CLI/webserver/测试程序集排除在统计外。
- CI（`.github/workflows/ci.yml` dotnet job）已挂 `--settings haoyue_tests/coverage.runsettings`，覆盖率跌破门槛 = 构建失败。
- **上调路线**：每次专项补测把门槛抬 2-5 个百分点，目标核心 >85%。门槛只升不降——降低 Threshold 需要在 ADR 中说明理由。

## 「失败日志分析」纳入可执行集成测试

此前 DefectAggregator 仅单元级覆盖，`evolution.inspect` 的 RPC 分发无直测。本次补齐端到端集成层（`DaemonServerTests.EvolutionInspect_*`）：

1. 脚本化失败回合写入真实 SQLite 事件日志（TurnStarted → 3 次同错误工具失败 → TurnCompleted + 用户负反馈）；
2. 经 daemon RPC `evolution.inspect` 触发聚合；
3. 断言 ToolFailureCluster（toolName=bash、occurrences=3、错误摘要）与 UserNegativeFeedback 报告均正确产出；空日志返回空报告。

失败信号「产生 → 落盘 → 聚合 → RPC」全链路现在是可执行回归，重构 Evolution 链路时不再依赖人工核验。

## 金字塔结构约定

- **单元层（最厚）**：各类行为单测（DefectAggregatorTests、ConfigSchemaTests、ProviderTests…），mock 边界。
- **集成层（中）**：复用 `DaemonServerTests` 的 server-fixture（Named Pipe 真实往返 + 注入 fake turn），覆盖 RPC 分发、配置管道、进化链路等跨组件行为。
- **端到端层（薄）**：desktop vitest 主进程测试 + CI desktop-package 打包冒烟；Electron GUI 冒烟在本机不可信（GPU 崩溃），以主进程逻辑直测替代。
- **非 Happy Path 最低要求**：每个 RPC 方法至少一个错误路径用例（参数缺失/非法值/冲突），契约测试已保证 schema 层面；业务层按方法补齐。
