# 全面审查与修复报告（2026-10-31）

> 基准：`main`（1.3.29 之后的工作区） · 范围：安全边界、可靠性、CI 护栏与文档一致性
> 结论：P0 5 项、P1 8 项、P2 5 项全部落地，验证基线见第 4 节。

## 0. 摘要

本轮审查覆盖「安全边界 → 运行时可靠性 → 工程护栏 → 依赖与文档」四层，共 18 项。最高优先级不是性能，而是**未受信工作区可通过配置取得自动执行权**、**覆盖率门槛实际未执行**、**跨语言契约类型与真实载荷不符**这三类「看起来有、实际没有」的护栏。

| 级别 | 项数 | 主题 |
|---|---|---|
| P0 | 5 | 工作区信任门禁、符号链接越界、覆盖率门禁失效、SDK 握手、契约类型 |
| P1 | 8 | CI 跨平台与供应链阻断、测试串行、Electron EOL、巨型类拆分、IPC 错误码、发布签名、webserver 迁移 |
| P2 | 5 | 零告警/AOT、事件队列背压、Unix socket 权限、文档漂移、Markdig 双版本 |

## 1. P0：安全与门禁

| 项 | 问题 | 处置 | 落点 |
|---|---|---|---|
| P0-1 | 工作区 `.haoyue/config.json` / `mcp/servers.json` 可携带 MCP stdio、verify 等自动执行命令；「打开一次」即取得执行权 | 引入受信清单 `~/.haoyue/trusted-workspaces.json`；未受信工作区整体忽略两份配置；`workspace.trust` / `workspace.untrust` 显式放行/收回；清单损坏按无受信处理；`workspace.get` 回传 `trusted` / `hasWorkspaceConfig` / `hasWorkspaceMcp` | `Workspaces/WorkspaceTrustStore.cs`、`WorkspaceManager.cs`、`DaemonServer.cs`、`DaemonContract.cs`、`WorkspaceTrustNotice.vue`；决策见 [ADR-20261031-workspace-trust](adr/ADR-20261031-workspace-trust.md) |
| P0-2 | 路径围栏按逻辑路径比较，符号链接 / junction 可指向围栏外 | `PathGuard.RealPath` 逐段解析链接后判定 `IsInside` 与凭证名单；链接链无法解析视为越界（fail closed） | `Tools/PathGuard.cs`、`haoyue_tests/PathGuardSymlinkTests.cs` |
| P0-3 | XPlat collector 只收集不判定，runsettings 的 Threshold 从未执行 | 改用 `coverlet.msbuild`，CI 以 `Threshold=70,55`、`ThresholdType=line,branch` 运行；删除 `coverage.runsettings` | `.github/workflows/ci.yml`、`haoyue_tests/haoyue_tests.csproj`、[测试金字塔与覆盖率门槛](测试金字塔与覆盖率门槛-2026-10-07.md) |
| P0-4 | TS SDK 握手等待 `ready`，daemon 实际回 `result`，真实连接首步即超时 | 握手改为等待 `result`，新增真实 daemon 集成测试（Linux CI 执行） | `sdks/typescript/src/client.ts`、`sdks/typescript/tests/client.test.mjs` |
| P0-5 | 契约把开放对象声明成单键对象（`config.save.fields`、`connectors.install.values`、`mcp env`） | 新增 `SAnyObject` / `SFreeObject` 建模；补齐工作区信任字段与两个新 RPC；快照与 TS 类型重新生成 | `Daemon/Contract/DaemonContract.cs`、`contracts/daemon-contract.json`、`sdks/typescript/src/contract.ts` |

## 2. P1：工程护栏与桌面

| 项 | 问题 | 处置 |
|---|---|---|

| P1-8 | 修改进程环境变量的测试并行执行，互相污染 | 新增 `ProcessEnvironmentCollection`（`DisableParallelization`），相关测试类统一加入 |
| P1-9 | Electron 43 已过维护窗口 | 升至 45.2.1，并固定官方下载源；桌面测试 / 类型检查 / 构建全绿 |

| P1-11 | IPC reject 后 `code` / `method` 丢失，渲染层只能看到字符串 | `daemon:request` 返回 `DaemonRpcResult` 结构化信封，渲染侧统一抛 `DaemonRequestError` |

## 5. 未覆盖与边界

- **RunTurnAsync 重构与 MCP 连接池化**：影响面超出本轮安全/门禁范围，按要求暂缓，需单独授权后实施。
- **桌面安装包冒烟**：本机验证到 `pnpm build` 为止，未重新生成 NSIS / 便携包；签名链路需在配置证书后由 Release 流水线验证。
- **信任门禁的语义边界**：未受信时是「忽略配置」而非删除文件；用户仍可在桌面端显式放行，放行前不连接工作区声明的 MCP 服务器。
- **Linux 实机**：Unix socket 权限与符号链接分支由 CI Linux 作业覆盖，本机（Windows）未复跑。
