# Desktop 桌面端

Haoyue Desktop 是基于 Electron 与 Vue 的桌面客户端。它通过本地 Daemon IPC 使用同一套 .NET Runtime，在图形界面中提供项目、任务、模型、工具和运行状态管理。CLI 仍然受支持，两种前端共享相同的 Provider、Profile、MCP、Skill 与会话数据。

## 获取与启动

### 使用已发布版本

<LatestRelease />

当前 Desktop 发布目标为 **Windows x64**。下载或接收发布包后，请保留整个 `Haoyue-win-x64` 文件夹并运行其中的 `Haoyue.exe`，不要只复制 EXE。

发布包已经包含自包含的 Runtime：

```text
Haoyue-win-x64/
├── Haoyue.exe
└── resources/
    └── runtime/
        └── haoyue.exe
```

终端用户不需要另行安装 .NET。Desktop 启动时会先连接已经运行的 Daemon；如果未找到，则自动启动随包附带的 Runtime。退出 Desktop 时，只会关闭由本次 Desktop 启动的 Runtime，不会终止用户自行启动的 Daemon。

### 从源码构建发布包

源码构建需要 Windows x64、.NET 10 SDK、Node.js、pnpm 与 Python 3。克隆仓库后，直接双击根目录的 `build.cmd`：

```text
build.cmd
```

`build.cmd` 会调用跨平台构建入口 `build.py`，依次安装依赖、运行 .NET 与 Desktop 测试、发布自包含 Runtime、构建 Electron 应用，并把最终文件放到：

```text
publish\Haoyue-win-x64\Haoyue.exe
```

需要从终端跳过测试或依赖安装时，可以使用：

```powershell
build.cmd --skip-tests
build.cmd --skip-install
```

请分发整个 `publish\Haoyue-win-x64` 文件夹。打包阶段需要下载 Electron 二进制；脚本会自动使用镜像并对临时网络错误重试。

## 界面结构与右栏工作区

主窗口固定为三栏：

- **左栏**常驻，承载「任务 / 项目 / 时间」三种视图与搜索框；顶部「新建任务」会标明这次创建的是**当前项目任务**还是**全局任务**，悬停可看到具体落点。时间视图下项目区仍然保留（默认收起），随时可展开。
- **中栏**是当前会话的对话流。
- **右栏工作区**用页签切换：**变更**（本次回合的文件 diff）、**历史**（Git 提交记录）、**工具**（本会话调用记录）、**浏览器**（内置浏览器）、**后台任务**。右栏可拖拽改变宽度，窄窗口下转为覆盖层。

设置、知识库、扩展（连接器 / 技能 / 专家）、计划任务与归档不是独立整页，而是右栏里的同级视图——切换它们时左栏与顶部导航保持原位，不会「整页跳走」。顶部的前进 / 后退按钮走浏览器式历史栈，可以按访问顺序回到上一个视图。

## 项目任务与不绑定项目的任务

Desktop 支持两类任务：

- **项目任务**绑定一个本地目录，可以读取和修改文件、打开项目终端、查看 Git 变更与提交历史。
- **不绑定项目的任务**没有固定工作目录，适合通用问答；它仍可使用本地文件、终端和 Git 工具，只是不显示项目级工具入口。

新建任务时不必立即创建 Runtime Session。只有第一次发送消息后，Desktop 才会创建并持久化会话。侧栏中的“任务”区域显示不绑定项目的任务；项目任务仍保留在各自项目节点下，可展开查看。

任务标题会根据首条提示词生成。你可以归档、恢复或删除任务，也可以批量处理全部任务或某个项目内的任务。已归档任务为只读状态。删除项目会永久删除该项目下的全部会话（包括已归档会话），但不会删除本地项目文件。

项目节点的属性里新增**「智能体」页签**：模型、提供商、温度、Agent 模式、语言、人格、验证命令（多行，失败即停）与系统提示词可设为该项目自己的默认值，写入 `<项目根>/.haoyue/config.json`。保存时只提交改动过的字段，不会把你在 CLI 或手写配置里的其他内容一并覆盖。

## 发起一次对话

1. 点击“新建任务”，选择一个项目，或使用不绑定目录的任务。
2. 在输入框选择 Agent 模式和 `provider/model`。Agent 模式是**全局**设置（下拉上标有「全局」），改动会写入当前工作区的 `.haoyue/config.json`；希望某个项目固定用自己的模式时，在项目属性 →「智能体」页签里设置项目级默认。
3. 输入要求并发送；也可以点击新任务页的预提示词卡片。卡片只会把文字填入输入框，**不会自动发送**。
4. 查看流式文本、思考状态、工具调用和完整错误信息。

支持视觉的模型会在输入区显示图片按钮，可一次选择多张 PNG、JPEG、WebP 或 GIF；Windows 截图后也可以在输入框直接按 `Ctrl+V` 添加剪贴板图片。发送前可以预览或逐张移除；发送后图片随 Session 保存。模型开始处理图片时，助手消息会显示“已查看”、对应文件名和缩略图，点击可再次预览。当前模型没有声明 `vision` 能力时，图片按钮会自动禁用。

输入框敲 `@` 引用当前项目的文件：候选由后台 `workspace.files` 现算，按「文件名前缀 > 文件名包含 > 路径包含」排序、最多 30 条，只给工作区相对路径且不读文件内容，并自动跳过 `.git`、`node_modules`、`bin`、`obj`、`dist`、`.haoyue` 与被忽略的内容，`.ssh`、`.aws`、`.env*` 这类凭证路径一律不出现。`↑`/`↓` 选择、`Enter` 或 `Tab` 插入、`Esc` 关闭。结果形如 `@src/App.cs`，Agent 按项目根解析，无需粘贴绝对路径；不绑定项目的任务不产生候选。

`Enter` 发送、`Shift+Enter` 换行；`Esc` 按当前情形依次承担：关闭弹窗（多层逐层关闭）、拒绝待确认的高危操作、停止当前回合（同 `Ctrl+.`）；`Ctrl+K` 聚焦侧栏搜索，`Ctrl+F` 在当前会话内查找。

每个任务的草稿各自保留：输入到一半的文字与尚未发送的图片、文件附件按任务存下，切走再切回自动恢复，发送成功或清空后即丢弃。

AI 正在输出时仍可继续输入。点击“发送”会把消息加入发送队列，本轮结束后按顺序自动发送；队列支持叠加和删除。点击队列消息的“引导”会立即把它作为附加指导交给当前 turn，不取消正在进行的 AI 请求。

输入区的联网（地球）按钮受两道开关控制：当前任务的联网开关，以及「设置 → 智能体 → 网页搜索」的全局开关。全局关闭时按钮置灰，悬停会说明去哪里打开——不会出现「点了没反应」。

项目任务顶部会显示完整工作区目录，并提供打开位置、终端、Git 变更、Git 历史和任务设置入口。任务设置弹窗把作用域分开：**推理深度**与**联网**只影响当前任务，**模型**与 **Agent 模式**是全局设置并在弹窗内明确标注。不绑定项目的任务不会显示项目目录或项目工具。

## 查看执行过程

输入框下方的状态行记录本轮账目：`N 轮 · N 步 | 缓存命中 X% | N tok/s | 输入 … tok · 输出 … tok | 上下文 Y%`。上下文占用按当前模型窗口折算，接近满窗时 Agent 会先压缩历史再继续。

每次工具调用折叠为一行（工具名、摘要、耗时），展开查看入参与结果，失败结果标注「错误」；写入类调用带 diff，汇总在「已编辑 N 个文件」卡片里，点文件名看增删行。

内置守卫拦下高危调用时弹出「高危操作需要你的确认」，列出工具、参数摘要与拦截原因：「本次允许」只放行这一次调用，「拒绝」或 120 秒不作答都不执行；批准与拒绝都会写入 `.haoyue/audit/tools.jsonl`。

手动停止的回合标注「已手动停止，回复可能不完整」，会话里同时写入 `>>> [turn interrupted]`。断线重连后按事件台账补播离线期间已结束的回合；后台异常退出留下的未完成回合会被判定为中断，而不是永远停在「正在运行」。

## 后台任务与计划任务

右栏「后台任务」页签把 daemon 的后台任务链路整条接到界面：派发一个完整的 Agent 回合后台执行（并发上限 4），列表实时显示状态与进度，可随时取消，也能一键跳回该任务对应的会话继续对话。关闭窗口或断线重连都不丢任务——进度按事件台账重放。

「计划任务」是与设置、归档同级的右栏视图，管理 cron 驱动的定时回合：每行直接显示上次运行的状态、时间、错误信息与输出摘要，「查看输出」展开全文，「打开本次会话」跳到那次运行产生的会话。失败会弹桌面通知；需要在外部系统触发回调时，按提示在「设置 → 智能体 → 专家参数」里配置 Webhook 地址。

## 历史与检索

会话打开时只加载最近 80 条消息，上方「加载更早的 N 条消息」继续向前翻页；历史图片的字节不随消息下发，缩略图按需读取。

侧栏搜索框输入 2 个字以上即跨会话全文检索（含已归档任务），结果列出标题、命中条数与命中片段，点击直接打开该会话。任务列表每组最多 40 条并按最后更新时间排序，当前任务一定保留在列表内，其余折叠在「显示全部（还有 N 个）」后面。

## 模型、Provider 与 API Key

打开“设置 → 模型与 Provider”可以：

- 新建、编辑、测试、启用或删除 Provider；
- 直接查看和修改保存在配置中的 API Key（解密显示，落盘为加密引用）；
- 在配置文件中保存和管理 API Key；
- 管理模型列表、Base URL、代理、超时和优先级；
- 配置提供商高级字段：Organization 与项目、并发线程数（本地推理）、KV 前缀复用（本地推理）、自定义请求头（密钥类请求头的值不回传，留空即保持原值）、思考档位映射；
- 为每个模型设置回退模型与输入 / 输出单价（用量页据此折算成本）；
- 选择视觉子智能体模型（自动挑选或指定一个支持视觉的模型）；
- **路由与容灾**：故障转移开关、本地→云回退（开启时红框提示会产生云端费用）、回退链排序与增删、负载均衡模式、重试与熔断（含链式预算）；
- 创建 Profile，并切换活动模型或路由策略；
- 本地模型（GGUF）附「加载配置」面板——上下文与性能、生成采样、思考、内存、推测解码、高级六分区的查看/编辑/保存，支持「加载并验证」与加载报告查看（详见 [Provider、模型与智能路由](/doc/providers)）。

![Haoyue Desktop 的模型与 Provider 管理](/screenshots/desktop/providers-and-models.png)

::: tip API Key 的显示规则
API Key 以 `secret:` 加密引用保存在 `~/.haoyue/config.json` 中（Windows DPAPI / Linux 密钥环），配置文件中不出现明文；Desktop 通过 `provider.list` 解密显示，编辑后即时重新加密。Runtime 不会从环境变量读取 API Key。
:::

保存后可立即点击“测试”。模型请求失败时，Desktop 会展示 Provider 名称、HTTP 状态码和服务端返回的完整错误信息，而不只显示笼统的 `LLM request failed`。

## 扩展、规则记忆与进化

侧栏「扩展」打开 Qoder 式扩展中心，三大类目一站式管理：

- **连接器（MCP）**：卡片式列表管理已连接的 MCP Server，可直接启停并进入详情编辑；「热门 MCP」模板一键接入，自定义服务器支持本地命令 / 远程 URL 与 OAuth / 访问令牌两种验证，保存后自动重载工具；
- **技能**：「已安装」视图启停与导入技能，「技能市场」一键安装官方技能；
- **专家**：内置领域专家目录，详情页一键「以此专家开始新任务」完成绑定（输入区显示专家徽章，可随时解除），也可以复制提示词粘贴到对话开头。

设置中心还提供：

- **智能体**：集中管理行为边界——网页搜索、探索者智能体（`delegate_task` 委派开关）与自动验证修复，以及一整套专家参数（最大步数、思考预算、工具输出上限、Bash 超时、会话留存、记忆固化、额外可读目录、人格与系统提示词）；
- **推理加速**：本地模型的**最终生效参数 + 来源层级**（模型级 / 提供商级 / 自适应档位）与实测吞吐一览，模型级覆盖提供商级时给出显式警告；提供预热、卸载、基准测试（TTFT / 解码 / 预填充 / 缓存命中）与显存治理（驻留模型数、并发、空闲卸载）。参数写入口只有「模型与提供商 → 模型加载设置」一处，本页仅能改提供商级默认；
- **规则与记忆**：管理层级 AGENTS.md 规则文件与长期记忆 MEMORY.md——编辑器支持新建（Ctrl+N）、删除规则文件和定位所在文件夹，Ctrl+S 快速保存，保存前自动脏检查；
- **进化**：缺陷信号一览、手动或定时自动反思、技能草稿的采纳与丢弃，详见[进化引擎](/doc/evolution)；
- **知识中心**：以「笔记本 → 来源 → 条目」管理 Agent 自动沉淀的经验——出处徽标、跨笔记本检索、标签筛选、导出备份与同义词表编辑，详见[知识中心](/doc/knowledge)；
- **诊断与用量**：检查工作区、配置和 Provider 健康状态，按近 7/14/30 天汇总调用、Token、延迟与成本，并附后台日志与诊断包入口；
- **高级设置**：额外可读目录白名单、Computer Use 与网络操作开关、全局配置的 JSON 编辑器（读侧脱敏，保存时只提交改动字段），底部危险区提供恢复出厂设置。

设置页顶部有搜索框，可按分区名与关键词直接跳到对应开关；后台未连接时整页转为只读并给出说明（此时空列表代表「读不到」而不是「没配置」），提示条 4 秒后自动收起。

## 后台日志与诊断包

Desktop 把 Runtime 的标准输出与标准错误逐行写入用户数据目录下的 `logs\daemon.log`（发布包即 `%APPDATA%\haoyue-desktop\logs\daemon.log`），超过 8 MB 会在下次启动前滚动为 `daemon.prev.log`。后台崩溃、显存不足、首字迟迟不来的线索都在这里。

「设置 → 诊断与用量」的**后台日志与诊断包**小节提供四个入口：**打开日志**（定位日志文件，尚未生成时定位目录）、**复制路径**、**刷新末尾**（界面内展示日志末尾 200 行与文件体积）、**导出诊断包**（保存对话框写出 `haoyue-诊断包-<时间戳>.txt`）。诊断包包含应用与后台状态、健康体检逐项结果、当前用量窗口的统计与脱敏后的日志末尾 400 行：`api_key`、`authorization`、`secret` 等键值以及 `Bearer`/`Basic` 头和 `sk-` 开头的密钥在读取时已替换为 `<已脱敏>`，不含配置文件正文与明文 API Key，可以放心转发。

::: tip 回合失败的提示会区分来源
后台未运行或连接断开（消息没送出，可点重连）、后台已收到但没有回第一个字（本地模型首次加载权重或显存不足，可能持续几分钟，应看后台日志）、其余失败（可重试并点击“查看技术详情”展开完整错误，详情随消息保存，重载后仍能点开）。
:::

## Runtime 连接行为

Desktop 会在启动时自动建立连接，并在连接丢失时进行有限次数的重连。如果重连仍失败，界面会展示具体错误并允许继续重试或退出。

常见检查项：

1. 确认发布目录中存在 `resources\runtime\haoyue.exe`。
2. 确认没有损坏或不兼容的旧 Daemon 占用 `\\.\pipe\haoyue-<用户名>`。
3. 在设置的“诊断与用量”中重新检查 Runtime 和 Provider。
4. 源码运行时，先执行 `build.cmd` 生成 Desktop 所需的 Runtime。

更底层的连接方法和协议字段见 [Daemon 与 IPC 协议](/doc/daemon)，其他问题见 [常见问题与排错](/doc/faq)。
