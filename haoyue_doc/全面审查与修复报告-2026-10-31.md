# 全面审查与修复报告（2026-10-31）

> 基准：`main`（1.3.29 之后的工作区） · 范围：安全边界、可靠性、CI 护栏与文档一致性
> 结论：P0 5 项、P1 8 项、P2 5 项全部落地；同日第二轮再收口 P1 1 项、P2 10 项（第 6 节），验证基线见第 4、7 节。

## 0. 摘要

本轮审查覆盖「安全边界 → 运行时可靠性 → 工程护栏 → 依赖与文档」四层，共 18 项。最高优先级不是性能，而是**未受信工作区可通过配置取得自动执行权**、**覆盖率门槛实际未执行**、**跨语言契约类型与真实载荷不符**这三类「看起来有、实际没有」的护栏。

| 级别 | 项数 | 主题 |
|---|---|---|
| P0 | 5 | 工作区信任门禁、符号链接越界、覆盖率门禁失效、SDK 握手、契约类型 |
| P1 | 8 | CI 跨平台与供应链阻断、测试串行、Electron EOL、巨型类拆分、IPC 错误码、发布签名、webserver 迁移 |
| P2 | 5 | 零告警/AOT、事件队列背压、Unix socket 权限、文档漂移、Markdig 双版本 |

## 5. 未覆盖与边界

- **MCP 连接池化**：影响面超出本轮安全/门禁范围，按要求暂缓，需单独授权后实施（回合主循环拆分已在第二轮完成，见第 6 节）。
- **桌面安装包冒烟**：本机验证到 `pnpm build` 为止，未重新生成 NSIS / 便携包；签名链路需在配置证书后由 Release 流水线验证。
- **信任门禁的语义边界**：未受信时是「忽略配置」而非删除文件；用户仍可在桌面端显式放行，放行前不连接工作区声明的 MCP 服务器。
- **Linux 实机**：Unix socket 权限与符号链接分支由 CI Linux 作业覆盖，本机（Windows）未复跑。

## 6. 第二轮补充审查（同日）

第一轮闭环后继续对同一工作区做第二轮扫描，聚焦「默认值不安全、边界缺失、护栏不可见」，共 11 项（P1 1 项、P2 10 项），全部落地。

| 项 | 问题 | 处置 |
|---|---|---|
| P1 浏览器权限收口 | 内置浏览器空白名单等于「全部放行」；webview 未收口摄像头 / 定位 / 串口等权限 | 空白名单只允许 localhost（127.x / ::1）；guest 会话仅保留全屏与剪贴板写入，其余权限一律拒绝；`target=_blank` 仍改为同视图加载并继续受白名单约束；`web_fetch` 的空白名单语义保持「未启用」不变，差异写入 README 与代码注释 |
| P2 PDF 导入桥 | doc_toolkit 参数靠字符串拼接，路径含空格 / 引号即错位；10 分钟超时后 python 进程与读管道仍存活 | 改用 `ArgumentList` 逐项传参；超时终止整棵进程树并抛出带文件名的明确错误 |
| P2 daemon 请求行 | 读行无上限，超大请求可把整行读进内存 | 新增 `BoundedLineReader`，握手与常规请求共用（避免预读丢字符）；超长行读取阶段截停并回 `invalid_request` |
| P2 回合主循环 | `RunTurnAsync` 单方法承载状态与工具结果处理，继续膨胀 | 抽出 `TurnState` 与 `Agent.Turn.cs`，主循环只保留编排；行为由现有用例锁定 |
| P2 前端 lint 与巨型组件 | 桌面端无 lint / 格式化约束，`App.vue` 与设置对话框持续膨胀 | ESLint 9（TS + Vue）+ Prettier 接入 CI；`guard:components` 行数预算脚本；脚本与纯逻辑拆出为独立模块并补单测 |
| P2 测试告警 | 测试工程放任可空性 / xUnit 分析器告警 | `TreatWarningsAsErrors=true` 清零；同步等待改 `ReadAsync` / `WaitAsync`，移除无意义 `.ConfigureAwait(false)` |
| P2 webserver 资源与安全头 | `wwwroot/lib` 手工 vendor 无完整性校验；响应缺 CSP / 防嗅探 / 防嵌入头 | `lib/manifest.json` + `VendoredLibTests`（哈希、版本下限、版本标记、引用覆盖）；`SecurityHeaders` 统一注入并在 API 与 HTML 双路径断言 |
| P2 桌面版本提示 | 打包版无任何更新感知 | `update-check` 纯逻辑 + 注入式网络测试；主进程 10 分钟缓存、仅打包版启动静默提示；「关于」页手动检查与下载入口 |
| P2 同步阻塞点 | 知识库抓取、Linux 浏览器修复、`Dispose()` 存在 sync-over-async | 全链路异步化；`Dispose()` 在线程池执行并以 `GetAwaiter().GetResult()` 收口，避免同步上下文死锁 |
| P2 测试稳定性与覆盖率可见性 | 时间敏感用例靠固定等待；CLI / webserver 覆盖率被总门槛掩盖 | 进程树用例改为「信号文件 + 事后触发」的确定性判定；SSE 看门狗首帧前置；OAuth 回环端口重试与回调窗口放宽；CLI 15/15、webserver 45/15 独立门槛 |
| P2 CI 动作 | Actions 主版本落后，`ubuntu-latest` 随镜像漂移 | checkout@v7 / setup-dotnet@v6 / cache@v6 / upload-artifact@v7 / download-artifact@v8 / setup-node@v7 / setup-python@v7 / pnpm@v6 / pages@v5；固定 `ubuntu-24.04` |
