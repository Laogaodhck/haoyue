### 遗留到下一轮（19 项，均有一致性影响但非致命；本期不动的原因标注）

**主进程（10）**：请求整体超时上限/心跳（长回合依赖事件流保活，贸加总超时会误杀长任务，需应用层心跳协议）；computer overlay 不区分会话且匹配标准不一致（需 sessionId 贯通事件，涉及协议改动）；部分回滚结果的「部分成功」表达（需 UI 层新增状态）；shutdown 外部 daemon 竞态（需 HAOYUE_MANAGED_BY_DESKTOP 握手确认）；SIGKILL 二段兜底；daemon 未绑父进程生命周期（Job Object，涉及是否为特性的一致性决策）；did-fail-load 兜底；whenReady 整体 catch；cleanupNewFileIfEmpty 同步 IO；darwin RID 缺失（当前不支持 macOS 打包，属产品决策）；多显示器 overlay。

**渲染层（7）**：steer 回滚竞态（需以 daemon 事件为唯一事实来源重构乐观 UI）；activeImageSources 每 delta 重建 data URL（需按 image.id 记忆化）；messageHeights/composerDrafts 不清理；optimizePrompt/supportsImages 异步竞态；Git 面板 refresh 无 catch；refreshAllProjectSessions 并行丢更新（极窄窗口）；SettingsDialog toast 无自动消失。

**Runtime（8）**：计划任务全局串行（_gate 全程持有）+ schedule.run 长时间挂起（需并发化调度循环）；MCP SSE 读无 idle timeout；连接 finally 清理与在途 dispatch 竞态（需 dispatch drain）；事件持久化同步写 SQLite 在流式热路径（需后台批量刷盘）；SessionGates/FileLocks 无界增长；BashTool 输出全量缓冲 + Windows 不杀进程树（需流式截断 + taskkill /T）；pipe 实例无 using；读循环行长度无上限；本地推理取消语义伪装成 stop；ScheduleService Dispose 竞态；usage 重试场景低估。

## 五、遗留风险与后续建议

1. **多客户端并发能力是当前最大短板**：本期修复了同会话互斥与重置协调，但调度循环串行、事件热路径同步写库、连接清理竞态等仍在「多客户端」这条线上，建议下一轮集中处理（每项独立可测）。
2. **BashTool 内存峰值**：超大输出命令（cat 大文件/刷日志）在并发回合下可放大内存占用，建议流式截断 + Windows 进程树击杀优先排期。
3. **steer 乐观 UI**：引导消息的超时回滚与事件到达存在双写竞态，建议以 daemon 'steer' 事件为唯一事实来源重构。
4. **macOS 打包**：electron-builder 配置含 mac target 但主进程 RID 解析无 darwin 分支，发布 macOS 前必须补齐。
5. 本报告与既有《功能现状分析报告-2026-10-04.md》互补：该文档面向「缺失功能」，本文档面向「已有功能的缺陷与健壮性」。
