## 2. P1：能力做了但用户拿不到 / 结果不可信

### 2.1 回合结果的诚实性（内核）

- **流式中断被判「任务完成」**：首 token 后不再换候选（`ProviderManager.cs:261`）；半截文本以 `interrupted` 收尾（`Agent.Streaming.cs:115-133`），而 `IsOutputTruncated` 不含该值（`Agent.cs:715-716`），回合正常终态、不续写；`ChatMessage` 无 finishReason 字段（`Agent.Context.cs:107-122`）——半截回答在历史里与完整回答**不可区分**。
- **空回答/拒绝回答误报成功**：连续两次空返回仍以 `done/任务完成` 收尾且 `error=null`（`Agent.cs:549-558`、`:634-637`）；全仓无 `refusal` 处理路径。这与刚修完的「回合无输出」是同一类故障的另一种表现形态。
- **策略拒绝与内部告警用户看不见**：拒绝只发 `WarningEvent`（`Agent.Tools.cs:76-83`），而契约的 stream/terminal/broadcast 三张名单里没有 warning（`DaemonContract.cs:111-124`，已复核），`DaemonServer` 亦无对应转发分支 → 桌面既看不到「为什么被拦」，也看不到上下文压缩失败等告警（`Agent.Context.cs:178-223`）。
- **成本闸门缺失**：`RecordUsage` 恒 `Cost=0`（`ProviderManager.cs:503`），`ComputeCost` 无生产调用方；`Routing.LoadBalance` 从未被 `BuildCandidates` 读取；无 per-turn/session/day 的 token 或费用上限，交互回合也没有墙钟预算（仅调度回合有 `ScheduledTurnTimeoutSeconds`）。
- **子代理脱离父台账**：委派未传 `undoRegistry`/`toolPolicy`（`AgentDelegation.cs:173-177`），因此 delegate 步骤恒不可补偿（`Agent.Tools.cs:145-148`），`agent.undo` 与崩溃对账会漏掉子代理的文件写入。
- **tool-calling 能力零探测**：`Capabilities.ToolCalling` 纯用户声明（`HaoyueConfig.cs:146`），`model.test` 只发文本，本地客户端完全忽略 `request.Tools`（`LocalLlmClient.cs:17`），而提示层仍按声明注入全量工具清单（`Agent.Prompting.cs:78-127`）→ 本地模型回合空谈且白烧 schema token。
- 上下文压缩仍属被动（丢≥4 条才触发，`Agent.cs:360-363`），超限当回合直接抛（`:391-403`），校准只对下回合生效。

### 2.2 记忆与检索的可达性与生命周期

- **语义检索对普通用户等于不存在**：四条件全要手配（模型条目 + `capabilities.embedding=true` + `knowledge.embeddingModel`），指引只散落在 `runbooks/deployment-isolation.md:114-135`；`knowledge.*` 与 `agent.memoryConsolidation*` 未登记进 `ConfigSchema.cs:36-74`，桌面 `src` 内搜 `embedding|semantic|向量` **零命中**（已复核）——用户无法知道自己处在语义还是纯词法，语义失效时三层空 `catch`（`KnowledgeSemanticIndex.cs:181-196`）不留任何痕迹。
- **首次检索在工具调用内同步嵌入全部缺向量条目**（`KnowledgeSemanticIndex.cs:165-179`），本地通道逐条串行且每条重建 `LLamaEmbedder`（`:252-266`）；单来源上限 200 chunk（`KnowledgeImport.cs:18-19`）→ 长回合卡死，与刚修完的「像没输出」同源。
- **融合权重名不副实**：词法侧按 `tokens.Count × 7` 归一，而 tokens 是同义词扩展 + CJK 二元切分后的集合（`KnowledgeSearchRanker.cs:58-100`），分母被成倍放大；语义侧按最大值归一恒有 1.0 项 → 名义 0.6/0.4 在真实分布下反转为语义主导；`Where(Final > 0)` 无绝对阈值，负例查询在混合路径会返回无关条目。嵌入侧还截断到 `MaxEmbedChars = 4000`（已复核 `KnowledgeSemanticIndex.cs:85,234`），而分块按 6000 字且无重叠——每条知识后 1/3 对语义永久不可见。
- **检索质量没有被度量**：`KnowledgeSearchEvaluationTests` 只测词法通道，混合路径用关键词查表式假向量（`KnowledgeSemanticTests.cs:33-44`）；agent-eval 七任务里**零个**记忆/检索任务（已复核任务清单）。0.6/0.4、4000 上限、Jaccard 0.45 均无指标支撑。
- **记忆只进不出**：MEMORY.md 追加写、无条数/体积上限、注入时 10 000 token 静默截断（`ContextPlanner.cs:134-149`），文件完整而模型看到缺半截；已取代事实只有墓碑不删除（`FactsStore.cs:196-207` 仅清过期，已复核 `SupersededBy` 无删除路径），容量淘汰把墓碑计入 100 条、可挤掉活跃事实；`Confidence` 只写不改，无命中次数/用户否认降级；全量事实整块注入、无 top-K 相关性筛选（`HaoyueRuntime.cs:246-284`）；固化只写事实层，从不写 MEMORY.md/知识库。
- **搜不到这件事进不了进化引擎**：`knowledge_search` 零命中以 Ok 返回（`KnowledgeTools.cs:37-41`），而聚合器只统计 `Success == false`（`DefectAggregator.cs:138-158`）→ 「补同义词/补知识」这类最有价值的反思永远不会发生。

### 2.3 桌面产品化断层

- **日志无 UI 入口**：`daemon.log` 路径未跨 preload，诊断页只有 KPI/图表/体检（`SettingsDialog.vue:1987-2124`）；同时所有失败统一文案「无法连接 Haoyue Daemon」（`App.vue:1487-1489`），30s 首事件超时也被说成连不上，且该文案不匹配 `extractModelError` 前缀（`app-helpers.ts:373`）→「查看技术详情」按钮不渲染。用户按我们上一轮的指引「先看 daemon.log」，却在产品里找不到那个文件。
- **重连即丢事件**：daemon 注释承诺重连端可经 `events.recent` 回放（`DaemonServer.cs:1995`），桌面**从未调用**（已复核：`events.recent` 仅出现在生成的类型清单里）。socket 掉线而 daemon 存活时 done/usage 永久丢失，`running` 只能等 daemon 重启的 `turn.interrupted` 才清。
- **跨会话搜索有 RPC 没 UI**：`session.search` 在契约里（`daemon-contract.gen.ts:184`），桌面零调用；`session.get` 无 limit，一次性返回全部消息含 base64 图（`DaemonAdminApi.cs:2519-2537`）；侧栏 threads 全量 v-for 无虚拟化。
- **工具过程不可展开**：工具行只有 div + title（`ConversationMessage.vue:264-272`），daemon 已发 `durationMs` 但 `ToolActivity` 无字段、handler 未读；重载后参数摘要丢失。
- **无人机审批链路**：全仓无 approve/approval 语义（方法清单可查），策略只有静态 deny → 「本次允许」这类交互不存在，P0 拦截后用户只能去改配置文件。
- **无自动更新**：`electron-updater` 未引入、build 无 publish 段、About 页无检查更新（已复核）；未签名告警亦无引导文案。输入侧无 `@` 文件引用、无上下文占用比例可视化（只报绝对 token，未除以 contextWindow）。
- **可访问性与本地化基本为零**：`lang="zh-CN"` 固定、无语言包、文案硬编码中文（与 README_EN 的存在相矛盾）；流式回复无 `aria-live`；停止按钮标称「Esc」（`Composer.vue:537`）实际只有 Ctrl+.。
- 崩溃恢复弱：未发消息草稿仅内存 Map（`App.vue:161`）。

## 5. 建议落地批次

1. **批次 A（安全边界，一周内）**：P0-1 去掉 `apiKey` 明文回传 → P0-3 读侧边界与敏感名单 → P0-4 computer_exec 纳入守卫与审计 → P0-5 审计目录只读 + Redactor 全入口 → P0-2 macOS 显式告警（Keychain 可后续）。每项都要有单测，并按惯例同步四份用户文档。
2. **批次 B（回合诚实性）**：warning 事件入契约 + 桌面可见、`interrupted`/`refusal`/空返回转为可判定终态并带 finishReason、补 per-turn token/费用预算闸门、委派接入父台账。
3. **批次 C（可观测与可达）**：daemon.log 的 UI 入口与导出诊断包、重连用 `events.recent` 回放 + seq 对账、工具行展开参数/结果/耗时、跨会话搜索面板、「本次允许」审批事件 + RPC + 审计闭环。
4. **批次 D（记忆/检索可信度）**：把 `knowledge.*`、`memoryConsolidation*` 登记进 ConfigSchema 并在桌面给出语义状态与一键建索引；修融合归一与 4000/6000 截断不一致、加绝对阈值与候选预筛、索引移出工具调用；补混合通道评测与 agent-eval 记忆任务；补 `PurgeSuperseded`、MEMORY.md 条目化压缩、事实注入改 top-K；检索零命中接入 DefectAggregator。
5. **批次 E（护栏固化）**：benchmarks 进 `Haoyue.slnx` 与 scheduled job、result schema 与逐方法错误码补齐、事件名穷举编译期护栏（renderer import 生成类型 + default 分支）、docs-facts 快照测试（119/881/160/7 由代码生成）、分支覆盖门槛与巨型类拆分 ADR（做或明确不做）。
