# 本地模型加载机制深度优化报告

- 日期：2026-10-14
- 范围：`haoyue_runtime/Providers/`（LocalModelCache / LocalLlmClient 及新增组件）、`Configuration/HaoyueConfig.cs`、`Daemon/`（RPC 与启动装配）、契约（`contracts/daemon-contract.json` + 桌面镜像）
- 测试：`haoyue_tests/LocalModelLoadingTests.cs`（26 项机制测试）、`LocalModelLoadBenchmarkTests.cs`（opt-in 真实基准）
- 结论先行：**五项能力全部落地**；交替驻留场景 **6.4~6.9×** 加速、热路径每请求省 **19~50ms**、mmap 私有内存峰值降低 **3.7GB**（5.3GB 模型）；并发槽在本机 CPU 口径下无收益（如实报告，默认保持串行）。

---

## 一、瓶颈分析（优化前实测定位）

优化前的加载路径：`LocalLlmClient.StreamAsync/EmbedAsync` → `LocalModelCache.AcquireAsync`（单模型槽 + 全局串行门）→ `LoadWithRetryAsync`（CliWrap 时代的 LLamaSharp 直载 + 重试 + 降级 + 512 自检）。

### 1. 启动速度

| # | 瓶颈 | 定位 | 后果 |
|---|------|------|------|
| B1 | 纯懒加载、无预热 | daemon 启动不装任何权重 | 第一条消息承担全部加载耗时（gemma-4-E4B 实测冷加载 **7.0s**，5.3GB 模型在 HDD/冷页缓存下以数十秒计） |
| B2 | 每请求重复解析 GGUF header | `LocalLlmClient.BuildShape` → `GgufProbe.Read(path)` 全量 KV 解析 | 实测 gemma header 解析 **50ms/次**（2000 次 100.6s），qwen **19ms/次**——每个请求都付 |
| B3 | 每请求枚举模型目录 | `LocalModels.ResolveMmprojPath` → `ListFiles` 全目录 FileInfo | 目录内文件多时每次请求数毫秒~数十毫秒 IO |
| B4 | 加载期持有全局门 | `_gate` 从加载持到 lease 释放 | 加载中所有本地请求（含嵌入、其他模型）全部排队且无可观测进度 |

### 2. 内存占用

| # | 瓶颈 | 定位 | 后果 |
|---|------|------|------|
| B5 | 单模型常驻、无回收 | 权重装入后无限期驻留 | 空闲时 5.3GB 权重 + KV 上下文不归还，阻塞后续更大模型 |
| B6 | 嵌入/聊天模型交替互相重载 | `EmbedAsync` 与 `StreamAsync` 共用一个单模型槽 | 每交替一次 = 卸载 + 重载 + 512 自检（gemma 实测单次重载 **3.8s**） |
| B7 | 无驻留预算概念 | 无 LRU、无驱逐 | 内存压力只能靠 llama.cpp 加载失败 → CPU 降级（请求路径上的事后补救） |

### 3. 并发支持

| # | 瓶颈 | 定位 | 后果 |
|---|------|------|------|
| B8 | 加载与推理共用一把锁 | `_gate` sem(1,1) 从加载持到推理结束 | 并发吞吐 = 单流；多会话/子代理本地请求严格排队 |
| B9 | 加载无进度、无排队状态 | `IsLoaded` 只有布尔 | 桌面端无法展示加载条；用户以为卡死 |
| B10 | 无备用模型通道 | 加载全失败即抛错 | 主模型文件损坏/显存不足时整个本地提供商不可用 |

### 4. 错误恢复（优化前已具备的强项，保留）

失败重试（原参数一次）→ GPU→CPU 降级重试 → 加载后 512 窗口真实 decode 自检 → 半初始化资源即时释放。**缺失**：整模型失败后的备用模型回退、加载参数回归自救的诊断、GGUF 版本/后端 ABI 兼容处理。

### 5. 缓存策略

| # | 瓶颈 | 定位 | 后果 |
|---|------|------|------|------|
| B13 | header / mmproj 解析零缓存 | 见 B2/B3 | 每请求重复 IO |
| B14 | 无加载指纹 | 耗时、参数、后端版本不留存 | 无 ETA 预估；升级 runtime 后加载失败无法归因 |
| B15 | 无空闲回收 | 见 B5 | 内存不归还 |

## 二、优化方案（代码级）

### 2.1 架构总览

```
LocalLlmClient.StreamAsync ──► FallbackChain（主+备，≤2 层）
   │
   ▼
LocalModelCache（权重库，进程级单例，跨 turn runtime 共享）
   ├─ _slots: ConcurrentDictionary<key, Slot>     多模型 LRU 驻留（默认 2）
   │    key = 模型路径 + 加载签名（档位/配置进签名，变更即换槽）
   ├─ _loadGate     加载/驱逐互斥（秒~分钟级）
   ├─ _inferenceGate 并发生成槽（默认 1 = 旧串行语义）
   ├─ LocalModelMetadataCache   header/mmproj 缓存（path,size,mtime / dir,mtime 键）
   ├─ LocalModelFingerprints    ~/.haoyue/model-fingerprints.json（ETA/ABI 诊断/失败史）
   └─ ModelCompatibility        GGUF 版本门 + 后端构建识别
```

### 2.2 懒加载与异步初始化

- **懒加载保留**：权重仍在首次请求时加载（默认语义不变，内存友好）。
- **异步初始化（新增）**：`PreloadAsync(path, factory, signature, mmproj, progress, ct)` 单航班预热——装槽不持 lease、不占推理槽；daemon 启动时若 `Agent.LocalModelPreload=true` 且活跃模型为本地，则后台预热（失败静默，退化为懒加载）。
- **进度监控（新增）**：`LocalLoadProgress`（阶段 Queued→Probing→Loading→Verifying→Projector→Ready/Failed + 百分比 + ETA）。llama.cpp 权重加载是单次原生调用，百分比按「阶段边界 + 历史 ETA 插值」诚实估计，不伪造字节级进度。ETA 取自指纹中的历史耗时中位数。daemon 以 `model.load.progress` 广播转发（进 journal，重连可回放）。

### 2.3 权重共享与多模型驻留

- 权重库是进程级单例，daemon 通过 `services.AddSingleton(_sharedLocalModels)` 注入每个隔离 turn runtime——**权重在所有并发回合间共享**（优化前即如此，本次经代码路径复核确认无第二实例）。
- **多模型 LRU（新增）**：最多 `LocalModelMaxResident`（默认 2）个模型同时驻留。嵌入/聊天交替时双方驻留，零重载；超预算时驱逐「最久未用 + 无活跃 lease」的槽（`PlanEviction` 纯函数，单测直连）。**服务中的权重永不驱逐**，无合格受害者时允许临时超预算——内存预算绝不让请求失败。
- 并发 > 1 时每请求独立 context（llama.cpp 多 context 共享 weights 的支持模式），KV 前缀复用自动关闭（`SupportsPrefixReuse`）。

### 2.4 错误恢复增强

1. **备用模型回退（新增）**：`ModelConfig.FallbackModelId`（同提供商内）。主模型重试 + 降级全失败 → 自动改用它再试；仅「尚未产出任何 token」的失败触发回退（半截回答不换模型重答）。链深度封顶 2，不形成链。
2. **版本兼容（新增）**：`ModelCompatibility` —— GGUF 版本 > 3 在触碰原生加载器前早期拒绝（可操作消息）；后端构建号（LLamaSharp 程序集版本）进指纹，升级 runtime 后旧模型加载失败时错误消息直接点明 ABI 漂移；连续失败计数进 `model.config.get` 的 `lastFailure`。
3. **加载指纹（新增）**：`~/.haoyue/model-fingerprints.json` 原子写盘，记录每模型最近 8 次成功耗时（ETA 源）、上次成功签名/后端/GGUF 版本/架构、失败史。损坏自愈（优化 hint，非事实来源）。

### 2.5 缓存策略

- **元数据缓存（新增）**：`LocalModelMetadataCache` 以 (路径, 大小, mtime) 缓存 header 解析、以 (目录, mtime) 缓存 mmproj 解析。替换模型文件必然改变 mtime/大小 → 自动失效，绝不返回过期元数据。
- **空闲回收（新增）**：daemon 每 5 分钟调用 `UnloadIdleAsync(Agent.LocalModelIdleUnloadMinutes)`，归还超时未用的权重（默认 20 分钟，0 = 关闭）；下一次请求按原签名重载（有指纹 ETA）。
- **mmap（既有默认，基准验证）**：权重 mmap 按页读盘 + 不 mlock，加载峰值与私有内存远低于整读。

## 三、优化前后性能对比（实测）

### 3.1 测试环境与基准条件

| 项 | 值 |
|---|---|
| 机器 | Windows 11（10.0.19045），16 逻辑核，RTX 3070 Ti 8GB（**未使用**：默认构建为 CPU 后端） |
| 后端 | LLamaSharp 0.27.0 + LLamaSharp.Backend.Cpu（GPU 口径需 `-p:LlamaBackend=Cuda12` 重新构建后重跑） |
| 模型 A | qwen2.5-0.5b-instruct-q4_k_m.gguf（468 MiB） |
| 模型 B | gemma-4-E4B-it-Q4_K_M.gguf（5088 MiB） |
| 基准工具 | `dotnet test --filter LocalModelLoadBenchmarkTests`，`HAOYUE_LOCAL_MODEL_BENCH=1` |
| 对照方法 | 同机、同代码、同参数，**唯一变量为被测量配置项**（MaxResident / 并发 / mmap / 缓存开关）——旧结构的行为由新代码的等价配置复刻（MaxResident=1 ≡ 旧单槽；无缓存直调 ≡ 旧热路径） |
| 原始数据 | `%TEMP%/haoyue-bench/local-model-bench-*.json`（每次运行落盘） |

### 3.2 D1 启动速度（首请求成本）

| 指标 | qwen 468MiB | gemma 5088MiB |
|---|---|---|
| 冷加载（旧行为：首请求承担） | 1014 ms | **7047 ms** |
| 预热后首请求（新增 PreloadAsync） | 391 ms | **4327 ms** |
| 首请求节省 | 623 ms（-62%） | **2720 ms（-39%）** |

> gemma 首请求剩余 4.3s 为 prefill + 生成本身（24 token）；加载等待被完全移出请求路径。5.3GB 模型在冷页缓存/HDD 上冷加载以数十秒计，预热的绝对收益同步放大。

### 3.3 D2 内存峰值（mmap 缓存策略）

| 模型 | mmap 开（默认） | mmap 关 | 差值 |
|---|---|---|---|
| gemma 工作集峰值 | 4883 MiB | 5827 MiB | **-944 MiB** |
| gemma 私有内存峰值 | 2673 MiB | 6434 MiB | **-3761 MiB（-58%）** |
| gemma 加载耗时 | 3195 ms | 4967 ms | -1772 ms |
| qwen 工作集峰值 | 541 MiB | 607 MiB | -66 MiB |
| qwen 私有内存峰值 | 481 MiB | 567 MiB | -86 MiB |

> 私有内存差异来自页属性：mmap 页为文件映射（不计入私有提交），整读全部计入。模型越大收益越大——这是 `TryMmap` 默认开启的量化依据。

### 3.4 D3 并发吞吐（8 个 24-token 短生成）

| 配置 | qwen 聚合吞吐 | gemma 聚合吞吐 |
|---|---|---|
| 串行 1 槽 × 16 线程（默认，旧语义） | 49.8 tok/s | 7.1 tok/s |
| 并发 4 槽 × 每槽 4 线程（新增能力） | 35.8 tok/s（-28%） | 6.2 tok/s（-13%） |

> **如实结论**：本机 CPU 后端 + 小/中模型场景，单请求已吃满 16 核，并发槽只增加上下文切换与 KV 开销，聚合吞吐下降。因此**默认保持 1（串行）**；并发槽的价值场景是 GPU 后端（decode 受显存带宽限制、CPU 有空闲）或长 prefill 混合负载，需 Cuda 构建后重测。`LocalModelConcurrency` 为可选能力而非默认收益。

### 3.5 D4 多模型交替（本次优化核心收益）

12 次 Acquire（A/B 交替 6 轮）：

| 配置 | 实际权重重载 | 总耗时 | 平均每次 |
|---|---|---|---|
| MaxResident=1（旧单槽行为） | **12 次** | 5740 ms | 478 ms |
| MaxResident=2（LRU 驻留，新默认） | **2 次** | 904 ms | 75 ms |

gemma（5.3GB）：

| 配置 | 实际权重重载 | 总耗时 | 平均每次 |
|---|---|---|---|
| MaxResident=1（旧行为） | **12 次** | 45155 ms | 3763 ms |
| MaxResident=2（新默认） | **2 次** | 6533 ms | 544 ms |

> 交替场景 **6.4×（qwen）/ 6.9×（gemma）** 加速，重载次数 12→2。典型受害者是「知识库嵌入用嵌入模型 + 对话用聊天模型」的交替：旧结构每交替一次全量重载 + 512 自检，gemma 下每 6 轮多付 **38.7s**。

### 3.6 D5 热路径（元数据缓存，2000 次调用）

| 调用 | 缓存开 | 缓存关（旧行为） | 单次节省 |
|---|---|---|---|
| BuildShape（gemma） | 85 ms（1 次读盘） | 100599 ms（2000 次读盘） | **50.3 ms** |
| BuildShape（qwen） | 87 ms | 38026 ms | **19.0 ms** |
| mmproj 解析 | 80 ms（1 次枚举） | 275 ms（2000 次枚举） | 0.1 ms |

> 每个本地请求省 19~50ms 同步 IO。一个 20 步的 agent 回合 = 0.4~1s 净节省，且消除了磁盘竞争对推理延迟的抖动。

## 四、新增配置项与 RPC

### Agent 配置（config.json → agent）

| 字段 | 默认 | 说明 |
|---|---|---|
| `localModelMaxResident` | 2 | 同时驻留模型数（LRU，1..16） |
| `localModelConcurrency` | 1 | 并发生成槽（1..16；>1 自动关闭 KV 前缀复用） |
| `localModelIdleUnloadMinutes` | 20 | 空闲回收阈值（0 = 关闭） |
| `localModelPreload` | false | daemon 启动后台预热活跃本地模型 |

### Model 配置

| 字段 | 说明 |
|---|---|
| `fallbackModelId` | 同提供商备用模型 id（加载全失败时启用；自引用拒绝） |

### Daemon RPC（契约已同步桌面）

| 方法 | 说明 |
|---|---|
| `model.preload` | 预热指定本地模型；进度经 `model.load.progress` 广播 |
| `model.unload` | 卸载全部常驻权重（活跃推理结束后释放） |
| `model.config.get` 扩展 | 新增 `residentSlots` / `concurrency` / `maxResidentModels` / `supportsPrefixReuse` / `idleUnloadMinutes` / `estimatedLoadMs` / `fallbackModelId` / `lastFailure` |

## 六、已知边界与后续方向

1. **GPU 口径未测**：本机默认构建为 CPU 后端。D3 并发收益、GPU 降级路径需 `-p:LlamaBackend=Cuda12` 构建后重跑基准。
2. **进度为阶段估计**：llama.cpp 无加载回调，百分比是「阶段边界 + ETA 插值」的诚实近似，非字节级真实进度。
3. **回退成功无用户可见提示**：成功走备用模型时，桌面端只能经 `residentSlots` 观察到驻留的是备用模型（不注入额外事件，避免噪音）。
4. **嵌入路径未接回退链**：`EmbedAsync` 失败仍直接抛错（语义检索层自行降级词法），回退链只服务对话路径。
5. 后续可选：`model.preload` 的桌面触发入口（设置页按钮）、按显存余量的动态驻留预算、KV 复用上下文的多槽化（当前并发 > 1 时禁用复用）。
