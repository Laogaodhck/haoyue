## 三、问题清单与修复

### P1（真实缺陷，已修复）http-api 等离线连接器安装后路径烤死，目标目录变动即永久失效

- **现象**：`mcp test` 中 http-api 连接失败——子进程秒退 "No such file or directory"，手动重装前不可恢复。
- **根因**：连接器安装时把随包分发的内置本地 MCP 服务器（`connectors/servers/haoyue_local_server.py`）的**绝对路径烤进** `mcp.servers` 的 args。该文件位于构建产物目录，被清理 / 移动 / 应用升级 / 目录改名后路径失效，而配置不会自愈——连接器保持 broken。
- **修复**：`McpManager.HealBundledServerArgs`（`haoyue_runtime/Mcp/McpManager.cs`）——连接前扫描 args，仅对「文件名为 `haoyue_local_server.py` 且当前不存在于磁盘」的条目重解析当前 bundled server 并替换；条目为全局配置实例时立即持久化。健康路径与其他参数一律不动。
- **复验**：`mcp test` 4/4（http-api 8 tools）；全局配置旧路径清零、新路径落盘；MCP / 连接器相关测试 76 项全过。

### 非缺陷记录（行为符合设计，不修复）

| 现象 | 判定 |
|---|---|
| read_file 缺必填参数返回明确消息 | 优雅降级：不崩溃 |
| bash 高危命令被 safe-delete 拦截 | 设计行为：批量删除防护闸门 |
| git 连接器 `--repository .` 相对 daemon cwd 解析 | 设计语义：真实 git 仓库下实连正常（12 tools） |
| network_diagnose dns 段 30s 超时 | 预期：超时保护 + 明确消息 |
