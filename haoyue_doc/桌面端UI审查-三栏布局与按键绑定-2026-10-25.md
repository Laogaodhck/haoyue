# Haoyue 桌面端 UI 审查：三栏布局、按键绑定与功能缺口

审查日期：2026-10-25
审查对象：`haoyue_desktop`（Electron + Vue 3 渲染层，约 29.4k 行）
对照后端：`haoyue_runtime`（daemon 124 个 RPC，见 `contracts/daemon-contract.json`；修复过程中新增 `config.get` 后为 125 个，见第 6.4 节）

---

## 0. 总体结论

三栏骨架是**成立**的，工程实现比多数同类产品扎实：`app-body` 用 CSS Grid 固定左栏 276px，`workspace-content` 用 Flex 承载「中栏自适应 + 右栏定宽可拖拽」，≤900px 时左栏转浮层、右栏转绝对定位覆盖层（`styles.css:5929`、`styles.css:7784`），没有出现三栏互相挤压、横向溢出的硬伤。

问题不在骨架，而在**信息架构与最后一公里**，集中在四类：

| 类别 | 数量 | 典型表现 |
|---|---|---|
| A. 按键在特定状态下静默失效 | 3 处 | 全局任务下点「更改」毫无反应；每条消息的联网开关被全局开关压制但外观仍为"开" |
| B. 后端能力零入口 | 6 组 / 约 25 个配置项 | 后台任务子系统（`task.*`）整套没有 UI；计划任务跑完看不到产出 |
| C. 同一配置多个入口、职责交叉 | 4 组 | 网络总开关在「智能体」和「高级设置」两处写同一个键；本地推理参数在两个页面写不同层级的字段 |
| D. 导航模型不统一 | 3 处 | 打开知识库/计划任务/设置时左栏整体消失，页面之间无法直接切换 |

下面按严重程度排序，全部结论都带 `file:line` 证据。

## 1. 三栏布局评估

### 1.1 左栏（SessionRail / `Sidebar.vue`）——职责过载，但可用

**承担了 6 类职责**：全局导航（新建任务/已归档/计划任务/扩展/知识库）、任务树、项目树、跨会话搜索、分组视图切换、设置入口。

做对的地方：
- 「按项目」与「按时间」双轴视图（`Sidebar.vue:78-96`），并持久化选择，符合任务量大后的真实心智；
- 本地过滤 + 远端 `session.search` 兜底（`Sidebar.vue:167-200`，≥2 字才远端、序号防竞态），长列表下"找不到会话"的经典问题被解决了；
- 内联重命名（双击 / F2，`Sidebar.vue:399-408`）替代重型弹窗，这是对的取舍；
- 上下文菜单会按可用空间自动向上/向下翻转（`Sidebar.vue:258-275`）。

**问题 1（P2）：两处「新建任务」作用域不同却长得一模一样。**
- 顶部主导航：`createTask(activeProjectId)` → 在**当前选中项目**下建任务（`Sidebar.vue:329`）；
- 「任务」区块标题旁的 `+`：`createTask()` → 建**全局任务**（`Sidebar.vue:362`）。

同一屏两个 `+`/笔形图标，一个是项目内、一个是全局，无文案区分、无 tooltip 说明。用户点错后得到的是"任务跑到别处去了"的困惑。**建议**：主按钮文案改为「新建任务」+ 当前作用域副标（如「在项目 haoyue 中」），或统一为"新建任务 → 弹层选作用域"。

**问题 2（P2）：切到「按时间」视图后，项目区整体消失。**
`<section v-if="viewMode === 'projects'" class="sidebar-section project-section">`（`Sidebar.vue:509`）——时间视图下「添加项目」按钮、项目属性、归档/删除项目全部不可达，必须先切回项目视图。这与"视图只影响会话列表的组织方式"的直觉不符。**建议**：项目区保留但折叠，或把「添加项目」提升为与视图无关的常驻入口。

### 1.2 中栏（`workspace-main`）——首屏动作密度偏高

`conversation-header` 一行内塞了 9 个可点元素：会话搜索框、连接状态按钮、打开位置、终端、更改、提交记录、工具活动、浏览器、任务设置、切换侧栏（`App.vue:2048-2103`）。其中：

- **4 个右栏入口按钮**（更改/提交记录/工具活动/浏览器）与右栏自己的 4 个页签是同一批动作的两个入口（见 2.1）；
- **「切换侧栏」出现两次**：标题栏 `PanelLeft`（`AppTitleBar.vue:175`）+ 会话头 `PanelRight`（`App.vue:2100`）。图标方向还相反（左 vs 右），语义上像两个不同功能；
- 「打开位置」是唯一带文字标签的按钮，其余全是裸图标，在 1280px 窄窗口下需要靠 tooltip 才能认清。

**建议**：右栏入口收敛为一组 segmented（或只保留右栏页签，header 只留一个"面板"开关）；删掉会话头的重复侧栏开关；给 4 个高频图标加 `aria-label` 之外的可见分组分隔。

### 1.3 右栏（`WorkDock.vue`）——设计最合理的一栏

单列复用（Git 更改 / 提交记录 / 工具活动 / 浏览器以页签切换，互不叠开）、拖拽手柄、宽度记忆、拖到 300px 以下自动关闭（`WorkDock.vue:65-75`）、内嵌模式隐藏子面板自身外壳（`embedded`）。这部分不需要改。

唯一问题是它与 header 的入口重复（见 2.1 与 3.3）。

### 1.4 跨栏问题（P2）：进入二级页面时三栏整体卸载

`<div class="app-body" v-show="activePage === 'main'">`（`App.vue:2019`）——知识库、计划任务、已归档、扩展、设置全部作为 `app-shell` 的直接子节点整页接管（`App.vue:2323-2341`）。后果：

- 左栏导航消失，**在"设置"里想切到"知识库"必须先 Esc 返回**；
- 任务树不可见，用户在设置里改配置时看不到后台任务状态；
- `embedded-page` 与 `settings-workbench` 两套页面外壳（`styles.css:876`）说明这是有意为之，但对"设置 ≠ 目的地，而是侧边抽屉"的主流心智是反的。

**建议（中期）**：把设置/知识库/扩展改为右栏（WorkDock）的同级页签或第二列抽屉，保持左栏常驻；短期至少在每个整页顶部保留返回 + 侧栏导航的等价入口（breadcrumb 或迷你 nav）。

## 2. 按键体检（冗余 / 缺失 / 无效）

### 2.1 P1｜全局任务下「更改」「提交记录」是死键

```js
// App.vue:433-438
function openWorkDock(tab: WorkDockTab): void {
  if (tab !== 'tools' && tab !== 'browser' && !activeProject.value) return   // ← 静默 return
```

而 header 里这两个按钮**没有** `v-if="activeProject"` 保护：

```html
<!-- App.vue:2084-2091：与上方「打开位置」「终端」不同，没有 activeProject 判断 -->
<button ... @click="openWorkDock('changes')"><Braces :size="18" /></button>
<button ... @click="openWorkDock('history')"><History :size="18" /></button>
```

全局任务（未绑定项目）占日常使用的相当比例（`App.vue:280` 的 `globalTaskActive`、`WelcomeEmpty` 的绑定项目引导都说明这是常态），此时点击这两个按钮**没有任何反应、没有 toast、没有 disabled 态**。

对照：标题栏菜单里同样的动作是正确处理的——`requiresProject: true`，无项目时按钮 `disabled`（`AppTitleBar.vue:209`）。同一产品内两套标准。

**修复**：header 两个按钮加 `:disabled="!activeProject"` 或 `v-if="activeProject"`，并给 `openWorkDock` 的静默 return 补一个 notify 兜底。

### 2.2 P1｜消息级联网开关会被全局开关静默压制

```csharp
// Agent.cs:393
var effectiveNetworkEnabled = session.Header.NetworkEnabled && agentConfig.NetworkEnabled;
```

三个开关的关系：

| 位置 | 写入 | 实际效果 |
|---|---|---|
| 设置 → 智能体 → 「网页搜索」 | `agent.config.set{networkEnabled}` → `Agent.NetworkEnabled` | 全局硬门 |
| 设置 → 高级设置 → 「全局网络访问」 | `advanced.set{networkEnabled}` → **同一个** `Agent.NetworkEnabled` | 全局硬门（重复入口） |
| 输入框地球图标（每条消息/task） | `session.update{networkEnabled}` | 被全局门 AND，全局关时**无效** |

用户在消息级把地球点亮 → 看起来"本任务联网已开启" → 实际工具仍被剥离，且 daemon 不会报错、UI 不会提示。**这是安全方向正确（fail-closed）但交互方向错误**：开关状态与实际能力不一致。

**修复**：Composer 由 App 层传入 `effectiveNetworkEnabled`（= session && global），全局关闭时把地球图标置灰并加 tooltip「全局网络访问已关闭，请先在设置中开启」。`App.vue:1910` 的 `changeNetwork` 同步补这条反馈。

### 2.3 P1｜设置页离线态：控件可点、文案误导、保存才报错

```ts
// SettingsDialog.vue:418
if (!props.open || !props.daemonConnected) return    // 直接返回，不留任何提示
```

daemon 未连接时打开「模型与提供商」，会看到 `providers.length === 0` → 渲染「**尚未配置提供商**」（`SettingsDialog.vue:1758`）。用户会以为配置丢了。同理开关类控件显示的是 ref 初始默认值（如 `networkEnabled = true`、`failoverEnabled = true`），与磁盘上的真实配置无关；用户拨动后要等 `advanced.set` 失败才看到错误。

**修复**：`daemonConnected === false` 时在 `settings-main` 顶部渲染统一横幅（"运行时离线，以下内容为只读/可能不是最新配置"）+ 禁用写操作按钮；空列表文案区分「离线」与「确实为空」两种原因。

### 2.4 P2｜「任务设置」名不副实

`TaskSettingsDialog.vue` 只有标题、工作目录（只读）、归档/删除。而任务级真实可配项——模型、Agent 模式、推理深度、联网——分散在 Composer 里，且其中两个（模型、模式）根本不是任务级（见 2.5）。入口名称与内容不匹配。

### 2.5 P2｜Agent 模式下拉的作用域与位置不符（含隐藏副作用）

```csharp
// DaemonServer.cs:2932-2943
private void SaveMode(string mode) {
    config.Agent.Mode = mode;              // 全局
    ConfigStore.Save();
    workspaceConfig.Mode = mode;           // 并写进 <workspace>/.haoyue/config.json
    File.WriteAllText(path, ...);
}
```

「编辑/计划/只读/自动」下拉放在输入框工具条里（`Composer.vue:790`），紧邻**任务级**的推理深度、联网——视觉上暗示"这是当前任务的属性"。实际是全局 + 当前工作区，切任务不变，并且会**静默往用户的项目目录写一个 config.json**。

对照：推理深度走 `session.update.reasoningLevel`（任务级），模型走 `model.switch`（全局）。三个相邻控件三种作用域，无任何标识。

**修复（择一）**：① 模式移到「任务设置」并明确写"对所有任务生效"；② 后端支持 `session.mode`，让模式真正成为任务属性；③ 至少在 tooltip 里写明作用域与"会写入项目 .haoyue/config.json"。

### 2.6 P2｜本地推理参数双入口，写不同层级字段，后者静默覆盖前者

| 入口 | 写入字段 | 位置 |
|---|---|---|
| 设置 → 推理加速 | `provider.GpuLayers` / `provider.FlashAttention` / `provider.KvCacheQuantization`；上下文长度写 **所有** `model.ContextWindow`（`DaemonAdminApi.cs:612-621`） | `SettingsDialog.vue:2367-2429` |
| 设置 → 模型与提供商 → 编辑 → 本地模型加载设置 | `model.Load.FlashAttention` / `Load.ContextLength` / `KV 量化` 等（`ModelLoadSettingsDialog.vue:9-26`） | `ProviderEditorDialog.vue:573` |

生效优先级在代码里是模型级覆盖提供级：

```csharp
// LocalLlmClient.cs:905 / 961
FlashAttention = load?.FlashAttention ?? provider.FlashAttention,
```

也就是说：只要用户动过一次「模型加载设置」（`Load` 变成非 null），「推理加速」页的 Flash Attention / KV 量化就**永久失效**，而界面没有任何提示。更麻烦的是"上下文长度"在两个页面写的是**不同的字段**（`Model.ContextWindow` vs `Load.ContextLength`），两者都"生效"，语义重叠。

**修复**：明确单一权威入口。建议「推理加速」页改为只读的"当前生效参数"看板（显示每个本地模型最终解析出的 gpuLayers/ctx/FA/KV/来源层级），写入统一收到「模型加载设置」。

### 2.7 P2｜同一全局开关在设置里出现两次

`agent.config.get/set{networkEnabled}` 与 `advanced.get/set{networkEnabled}` 读写的都是 `Config.Agent.NetworkEnabled`（`DaemonAdminApi.cs:155` / `:313`，`SetAgentConfig:222` / `SetAdvancedConfigAsync:472`）。UI 侧两个独立分区各自渲染一个开关：

- 智能体 → 「网页搜索」（`SettingsDialog.vue:2482`）
- 高级设置 → 「全局网络访问（联网搜索与抓取）」（`SettingsDialog.vue:2552`）

两处文案不同、位置相隔两页，实际是同一个比特。且「高级设置」的 `toggleNetworkEnabled` 会顺带提交 `failoverEnabled` / `deepSeekOptimizationEnabled` 两个 ref（`:846-854`）——若用户从未进过对应页面，这里提交的是初始默认值，存在把服务端配置覆盖成默认值的风险面。

**修复**：删掉其中一处（建议保留「智能体」下的语义化描述），或把高级设置改为只读引用 + "去智能体页修改"跳转。

同理，**模型切换有 3 个入口**（Composer 下拉、模型与提供商→使用、智能体→根模型→使用），其中"智能体→根模型"与"模型与提供商→活动模型"完全等价。

### 2.8 P3｜其他冗余与装饰键

- **标题栏「后退/前进」永久 disabled**（`AppTitleBar.vue:178-183`）：纯装饰，占用最宝贵的左上一格。要么实现会话浏览历史（这类应用价值很高），要么删除。
- **「导出会话」只有 slash 命令**（`composer-slash.ts:24`），没有按钮/菜单项；导出是低频但强需求动作，藏在下拉建议里发现率极低。
- **右栏入口重复**：header 4 个按钮 + WorkDock 4 个页签。
- **设置无搜索**：10 个分区、约 60 个控件，"单回合费用上限"这类项只能靠记忆翻页。
- **成功提示不自动消失**：`notice` 一旦设置就常驻（`SettingsDialog.vue:2636-2646` 无定时器），直到下一次操作清空。

## 3. 后端已支持、界面无入口（功能缺口）

判定方法：以 `contracts/daemon-contract.json` 的 124 个方法 + `HaoyueConfig.cs` 的字段全集为基准，反查 `haoyue_desktop/src` 的引用。13 个 RPC 完全零引用；另有大量配置字段无任何读写入口（连 `config.save` 的 CLI 通道也未暴露，只能手改 `~/.haoyue/config.json`）。

### 3.1 P1｜后台任务子系统整套没有 UI（`task.start/get/list/cancel`）

`BackgroundTaskService` 已完整实现（`DaemonServer.cs:74/227/1414-1481`），终态迁移通过 `BackgroundTaskEvent` 广播（`Events/RuntimeEvents.cs:197`），`task.start` 提交后可 `task.list` / `task.get` / `task.cancel`。

而渲染层对这 4 个方法的引用数为 **0**。用户既不能派发后台回合，也不能查看/取消已在跑的后台任务。这是本次审查发现的**最大能力黑洞**——它不是配置项，而是一个完整功能面。

**建议**：右栏增加「后台任务」页签（与"工具活动"并列，天然同构）：列表 + 状态 + 取消 + 点击跳转对应会话。工作量小（协议、事件、状态机都已就绪），收益高。

### 3.2 P1｜计划任务看不到运行结果

后端 `ScheduledTask` 保存了 `LastRunAt` / `LastStatus` / `LastError` / **`LastOutput`**（`Scheduling/ScheduleModels.cs:26-30`）。

界面只渲染 `nextRunAt`、状态文案和提示词（`ScheduledTasksDialog.vue:289-291`），**`LastOutput`、`LastError`、`LastRunAt` 三个字段一个都没用**。

后果：用户配了"每天 9 点生成日报"，第二天打开界面只能看到"成功"两个字，看不到日报正文，也没有入口跳到那次运行的会话。功能闭环断裂。

**建议**：列表行展开显示 `lastOutput` 摘要（点击看全文）、`lastError` 高亮、`lastRunAt` 相对时间，并提供"打开本次会话"。

### 3.3 P1｜本地模型的显存治理与基准测试零入口

对 8GB 显卡用户，这些是刚需，而它们全部只在 RPC 层：

| RPC | 能力 | 界面 |
|---|---|---|
| `model.preload` | 预热权重（不占推理槽，进度经 `model.load.progress` 广播） | 无 |
| `model.unload` | 卸载全部常驻权重，归还显存 | 无 |
| `model.benchmark` | 多轮 TTFT / decode / prefill 速率 + KV 复用命中率 | 无 |

对应配置项同样无入口：`Agent.LocalModelPreload`（默认 true）、`LocalModelMaxResident`（同时驻留上限，默认 2）、`LocalModelConcurrency`（并发槽，默认 1）、`LocalModelIdleUnloadMinutes`（空闲回收，默认 20）。

**建议**：在「推理加速」页加"当前驻留状态"卡片（已加载模型 / 显存占用 / 空闲倒计时）+「立即卸载」+「重跑基准」；四个配置项并入同一卡片。

### 3.4 P1｜路由与容灾的一批开关无入口（含防意外计费开关）

`routing.get` 已经把 `localFailoverToCloud` 返回给前端（`DaemonAdminApi.cs:149`），`SetRoutingConfig` 也支持写入（`:453-460`），但 `SettingsDialog` 只读 `failoverEnabled` / `deepSeekOptimizationEnabled` 两个字段。

被隐藏的还有：
- `Routing.LocalFailoverToCloud`（默认 false，注释明确写着"防 surprise billing 的有意设计"——一个**为防止意外账单**而存在的开关，却没有任何界面能让用户**主动开启**，等于该设计对 GUI 用户不可达）；
- `Routing.Fallback`（全局回退链，有序列表）；
- `Routing.LoadBalance`（priority / roundRobin / leastUsed / lowestCost / fastest / sticky）；
- `Routing.Retry.*`（MaxAttempts、BaseDelay、MaxDelay、FallbackRetryAttempts、CircuitBreakThreshold、CircuitCooldown、**ChainBudgetSeconds**）。

**建议**：「模型与提供商」增设"路由与容灾"子区：回退链拖拽排序、负载均衡下拉、重试/熔断折叠区、本地→云回退开关（带费用警告文案）。

### 3.5 P2｜智能体高级参数只能手改 JSON

`SetAgentConfig` 只覆盖 8 个字段（network / delegation / autoVerify / 三个预算 / compaction / vision / toolPolicy / bashSandbox）。以下字段**既无 UI、也不在任何 RPC 参数白名单里**，只能手改 `~/.haoyue/config.json`：

`MaxSteps`（回合步数上限）、`ThinkingBudgetTokens`（本地思考预算）、`MaxToolOutputChars`、`BashTimeoutSeconds`、`ScheduledTurnTimeoutSeconds`、`MaxRepairAttempts`、`MaxOutputContinuations`、`EnableContextCompaction`（总开关；只有比例可调——关掉压缩这件事做不到）、`Personality`（pragmatic/friendly）、`SystemPrompt`、`DelegationMaxDepth`、`DelegationMaxPerTurn`、`FactsInjectTopK`、`ExtraReadableRoots`（额外可读目录）、`SessionRetentionDays`（90 天自动归档——**有数据影响却无界面提示**）、`MemoryConsolidationEnabled` / `MemoryConsolidationLookbackDays`。

**建议分两批**：第一批把"会改变成本/安全/数据留存"的四项提到界面（MaxSteps、ThinkingBudgetTokens、SessionRetentionDays、ExtraReadableRoots）；其余归入「高级设置 → 专家参数（JSON 编辑器）」，用 `config.save` 做带 schema 校验的直改，避免用户去翻文件。

### 3.6 P2｜工作区级配置（`<workspace>/.haoyue/config.json`）全无 UI

`WorkspaceConfig` 支持逐项目覆盖：`Provider`、`Model`、`Temperature`、`Mode`、`SystemPrompt`、`Personality`、`Language`、`DisabledSkills`、`DisabledTools`、`Mcp`、`AutoVerify`、`VerifyCommand` / `VerifyCommands`（多步验证链）。

界面侧：`ProjectPropertiesDialog` 只做了 MCP 与技能开关（`ProjectPropertiesDialog.vue:76-81`），其余字段零入口。其中 **`VerifyCommands`（构建→测试链，支持 fail-fast）** 是自动验证功能的核心，用户若想给一个非标准项目配 `python -m pytest`，只能自己摸到项目目录下建 `.haoyue/config.json`。

**建议**：项目属性 → 「智能体」页签，暴露 VerifyCommands（多行命令列表）、项目默认模型、项目语言、AutoVerify 覆盖。

### 3.7 P2｜其他零入口项

| 配置 / RPC | 说明 | 建议 |
|---|---|---|
| `Agent.ScheduleWebhookUrl` | 计划任务结果回调（无桌面连接时唯一通知通道） | 计划任务页 → 通知设置 |
| `ImageGen.Model` / `ImageGen.Size` | 图像生成模型与尺寸；未配时 `image_generate` 工具自动隐藏 | 模型与提供商 → 图像生成 |
| `DocRender.Enabled` / `ToolkitPath` / `PythonPath` | `doc_render` 工具（Python doc_toolkit）；Python 缺失工具自动隐藏，用户无从得知原因 | 高级设置 → 文档渲染 |
| `Knowledge.EmbeddingModel` | 语义检索模型；`semanticEnabled` 有 UI，模型选择没有 | 知识库页 → 语义检索卡片 |
| `Provider.Headers` / `Organization` / `ReasoningEffortMap` / `LocalPrefixReuse` / `Threads` | 自定义鉴权头、组织、思考档位映射、KV 前缀复用 | 提供商编辑器 → 高级折叠 |
| `Model.FallbackModelId` / `InputPricePerMTok` / `OutputPricePerMTok` | 本地模型备用回退、定价（定价影响费用预算与用量统计口径） | 模型编辑 → 高级 |
| `config.save` | 通用字段级补丁（CLI 单写者通道） | 见 3.5 建议 |
| `lock.list` / `session.resume` / `model.config.get` / `contract.export` / `protocol.info` / `ping` / `doctor` | 开发者/内部诊断接口 | 可不做 UI；`lock.list` 可并入诊断页 |

## 4. 改进建议（按优先级与投入产出比）

### 第一批：低成本、立刻消除"点了没用"的体验（约 1 天）

1. header「更改/提交记录」加 `disabled`/`v-if`（2.1），并给 `openWorkDock` 补 notify 兜底。
2. Composer 联网图标改读 `effectiveNetworkEnabled`，全局关闭时置灰 + tooltip（2.2）。
3. 设置页加离线横幅，禁用写操作；空列表文案区分"离线"与"确为空"（2.3）。
4. 删除标题栏「后退/前进」装饰键，或实现会话浏览历史（2.8）。
5. `notice` 增加 4s 自动消失。
6. 计划任务行展示 `lastOutput` / `lastError` / `lastRunAt`（3.2）——纯渲染改动，收益极高。

### 第二批：补关键能力缺口（约 3–5 天）

8. 「推理加速」页改为"当前生效参数 + 驻留状态"看板，接入 `model.preload/unload/benchmark` 与四个 `LocalModel*` 配置（3.3、2.6）。
9. 「模型与提供商」新增"路由与容灾"子区（3.4），首屏必须包含 `LocalFailoverToCloud` 并附费用警告。
10. 项目属性补 VerifyCommands / 项目模型 / 项目语言（3.6）。

### 第三批：信息架构调整（需要设计与评审，约 1–2 周）

11. **设置分区重划**（2.7、2.5）：
    - 「常规」只留外观/语言/快捷键/Runtime；**移出恢复出厂设置**到「高级设置」底部独立危险区；
    - 「模型与提供商」吸收路由容灾、视觉子模型、本地推理、图像生成 —— 凡是"模型相关"的都归这里；
    - 「智能体」只留行为开关（联网、委派、自动验证、预算、压缩、工具策略）；
    - 「高级设置」只留专家参数/白名单/实验性插件。
12. **导航模型统一**（1.4）：设置/知识库/扩展/计划任务/归档改为右栏同级视图，左栏常驻；保留 `activePage` 作为右栏 tab 状态而非整页开关。
13. **左栏作用域显性化**（1.1）：两处「新建任务」合并为一个带作用域选择器的入口；时间视图下保留项目区折叠。
14. **配置单一权威化**（2.5、2.6）：模式改任务级（或明确全局）；本地推理参数写入只保留「模型加载设置」一处。
