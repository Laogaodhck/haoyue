# 模型加载模块增强实施方案

- 日期：2026-10-10
- 范围：`haoyue_runtime/Providers`、`haoyue_runtime/Daemon`、`haoyue_runtime/Configuration`、`haoyue_desktop`（模型配置页）、契约与测试
- 对应提交：`47d7898`
- 目标：提升模型加载速度、降低内存峰值、支持更大规模模型、完善加载容错（自动重试 / 异常捕获 / 资源释放）、加载后自动推理验证、兼容单模态与多模态（mmproj），并新增模型加载配置页面与加载流程对接

---

## 一、方案总览

| 目标 | 采取的策略 |
|---|---|
| 加载速度 | mmap 内存映射加载（默认开）；`n_batch` / `ubatch` 评估与物理批大小可调；RoPE 覆盖支持；权重按需懒加载（请求到达才加载）保持不变 |
| 内存峰值 | `keepModelInMemory`（mlock 锁页）默认关闭；mmap 映射避免整模型一次性读入；K/V cache 独立量化（q8_0 / q4_0）与统一 KV cache；新增 `UnloadAsync` 主动卸载归还内存/显存 |
| 更大模型 | 显式上下文长度只向训练值钳制（解除 32k 实用上限约束）；GPU 卸载失败自动降级 CPU-only；mlock 关闭后超大权重不要求连续锁页 |
| 稳定容错 | `LoadWithRetryAsync` 三段尝试（原参数 → 退避重试 → CPU 降级），每次尝试的半初始化资源即时 Dispose；加载 gate 以 finally + 所有权标志保证恰好释放一次；全部失败时汇总各次错误抛出 |
| 加载验证 | 每次加载成功即用 512 窗口小上下文做真实 tokenize + decode 自检；权重损坏、上下文创建失败在加载期暴露并触发重试/降级；加载报告（尝试次数/降级/耗时）经 RPC 暴露 |
| 单/多模态 | mmproj 损坏仅降级纯文本不失败加载；配置页可显式设置 `mmprojPath`（清空恢复同目录自动探测）；带图请求走既有 mtmd 路径 |

## 四、诚实边界（未生效项）

以下字段配置页可查看/保存，但运行时暂不生效（页面已标注 Experimental），待运行时能力补齐后启用：

- 推测解码（`speculativeDecoding`）——进程内草稿模型流水线未实现
- 上下文检查点（`contextCheckpoints`）、最大并发预测数（`maxConcurrentPredictions`）——本地推理在进程内严格串行
- 聊天模板覆盖（`chatTemplate`）、llama.cpp 参数覆盖（`llamaCppOverride`）
- 思考预算（`reasoningBudget`）由 agent 层（`AgentConfig.ThinkingBudgetTokens`）统一执行，该值保存并透传展示
