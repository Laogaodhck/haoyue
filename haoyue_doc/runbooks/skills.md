# 官方技能 Runbook（how-to-use）

> 护栏：`haoyue_tests/RunbookCoverageTests` 保证 `OfficialSkillCatalog` 中每个 slug 都有 `## <slug>` 章节。
> 新增官方技能时先在本文件补章节，再合入代码（见 [README](README.md)）。

## translator

- **适用场景**：多语言互译、译文润色、表达咨询。
- **触发方式**：技能市场安装后，对话中出现翻译意图即触发；未触发时用 declare_skill 显式加载。
- **边界**：代码/命令行/日志不翻译；默认只输出译文。

## polish

- **适用场景**：中文文本纠错、去翻译腔、风格统一。
- **触发方式**：提供中文文本并要求润色/纠错/改写。
- **边界**：不改事实、不堆砌辞藻；默认直接输出润色全文。

## report-writer

- **适用场景**：周报/日报/月报/项目总结/述职材料。
- **触发方式**：要求撰写汇报类文本；素材不足时技能会先提问补齐。
- **边界**：结果导向，标准结构为「本期完成/进行中/风险与阻塞/下期计划」。

## meeting-notes

- **适用场景**：从会议记录/转写/零散要点提炼纪要。
- **触发方式**：提供会议素材并要求整理。
- **边界**：输出议题、决议、行动项（含负责人与截止时间），不虚构未提及的决定。

## prompt-engineer

- **适用场景**：系统提示词/agent 人设/工具描述的设计与优化。
- **触发方式**：提供现有 prompt 或描述目标行为并要求优化。
- **边界**：改写会说明每处修改的意图，便于人工取舍。

## code-review

- **适用场景**：对一段代码/一次变更做规范性、缺陷、可读性审查。
- **触发方式**：提供 diff 或文件并要求 review。
- **边界**：只指出问题与依据，不直接改文件；按严重程度分级输出。

## unit-test-writer

- **适用场景**：为既有代码补单元测试（边界、异常、回归用例）。
- **触发方式**：提供目标代码并要求写测试。
- **边界**：遵循目标项目既有测试框架与命名约定，不引入新依赖。

## sql-expert

- **适用场景**：SQL 编写、优化建议、执行计划解读。
- **触发方式**：提供 schema/查询并说明数据库类型。
- **边界**：区分方言（PostgreSQL/MySQL/SQLite），不输出未验证的性能承诺。

## regex-expert

- **适用场景**：正则表达式的设计、解释、调试。
- **触发方式**：提供匹配目标样本并要求构造/解释正则。
- **边界**：给出测试用例验证匹配/不匹配，避免灾难性回溯写法。

## git-commit

- **适用场景**：生成符合规范的提交信息、整理提交拆分建议。
- **触发方式**：给出变更内容或 diff 并要求提交信息。
- **边界**：遵循仓库现有提交风格（类型前缀/作用域），不代为执行 push。
