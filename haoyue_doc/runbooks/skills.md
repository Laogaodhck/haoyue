# 官方技能 Runbook（how-to-use）

> 护栏：`haoyue_tests/RunbookCoverageTests` 保证 `OfficialSkillCatalog` 中每个 slug 都有 `## <slug>` 章节。
> 新增官方技能时先在本文件补章节，再合入代码（见 [README](README.md)）。

## translator

- **适用场景**：多语言互译、译文润色、表达咨询。
- **触发方式**：技能市场安装后，对话中出现翻译意图即触发；未触发时用 declare_skill 显式加载。
- **边界**：代码/命令行/日志不翻译；默认只输出译文。

## polish

- **适用场景**：中文文本纠错、去翻译腔、风格统一。
- **触发方式**：提供中文文本并要求润色/纠错/改写。
- **边界**：不改事实、不堆砌辞藻；默认直接输出润色全文。

## report-writer

- **适用场景**：周报/日报/月报/项目总结/述职材料。
- **触发方式**：要求撰写汇报类文本；素材不足时技能会先提问补齐。
- **边界**：结果导向，标准结构为「本期完成/进行中/风险与阻塞/下期计划」。

## meeting-notes

- **适用场景**：从会议记录/转写/零散要点提炼纪要。
- **触发方式**：提供会议素材并要求整理。
- **边界**：输出议题、决议、行动项（含负责人与截止时间），不虚构未提及的决定。

## prompt-engineer

- **适用场景**：系统提示词/agent 人设/工具描述的设计与优化。
- **触发方式**：提供现有 prompt 或描述目标行为并要求优化。
- **边界**：改写会说明每处修改的意图，便于人工取舍。

## code-review

- **适用场景**：对一段代码/一次变更做规范性、缺陷、可读性审查。
- **触发方式**：提供 diff 或文件并要求 review。
- **边界**：只指出问题与依据，不直接改文件；按严重程度分级输出。

## unit-test-writer

- **适用场景**：为既有代码补单元测试（边界、异常、回归用例）。
- **触发方式**：提供目标代码并要求写测试。
- **边界**：遵循目标项目既有测试框架与命名约定，不引入新依赖。

## sql-expert

- **适用场景**：SQL 编写、优化建议、执行计划解读。
- **触发方式**：提供 schema/查询并说明数据库类型。
- **边界**：区分方言（PostgreSQL/MySQL/SQLite），不输出未验证的性能承诺。

## regex-expert

- **适用场景**：正则表达式的设计、解释、调试。
- **触发方式**：提供匹配目标样本并要求构造/解释正则。
- **边界**：给出测试用例验证匹配/不匹配，避免灾难性回溯写法。

## git-commit

- **适用场景**：生成符合规范的提交信息、整理提交拆分建议。
- **触发方式**：给出变更内容或 diff 并要求提交信息。
- **边界**：遵循仓库现有提交风格（类型前缀/作用域），不代为执行 push。

## docx-report

- **适用场景**：把报告、总结、方案、纪要整理成正式 Word 文档交付。
- **触发方式**：要求「写成 Word / 出一份报告文档」时触发；内部以 doc_render（format=docx）落地。
- **边界**：产物落 `.haoyue/outputs/documents/`；工具不可用时退回 Markdown 全文交付。

## xlsx-dataset

- **适用场景**：把结构化数据整理为 Excel 表格（花名册、清单、统计表）。
- **触发方式**：要求「做成 Excel / 整理成表格」时触发；内部以 doc_render（format=xlsx）落地。
- **边界**：Markdown 管道表格映射为真实行列；缺失值标「待确认」，不臆造数据。

## pptx-deck

- **适用场景**：把大纲或要点组织成 PPT 演示稿（汇报、培训、宣讲）。
- **触发方式**：要求「做成 PPT / 出演示稿」时触发；内部以 doc_render（format=pptx）落地。
- **边界**：每个一级标题一页；工具不可用时退回分页 Markdown 大纲。

## deep-research

- **适用场景**：主题深度调研、研究报告、多源对比论证。
- **触发方式**：「深度调研 / 研究报告 / 帮我研究一下 X」。
- **边界**：固定五步流程（拆解→并行检索→逐源核验→事实沉淀→成文）；引用必须可点击，单一来源显式标注。

## weekly-report

- **适用场景**：周报/周总结/进展汇报。
- **触发方式**：「写周报 / 本周总结」。
- **边界**：固定四段结构；量化优先，300 字内精简版与细节版按接收方区分。

## data-cleaning

- **适用场景**：表数据去重、补全、格式归一。
- **触发方式**：「清洗 / 整理这批数据」。
- **边界**：先摸底再动手；清洗规则有歧义先问；缺失值不臆造。

## ocr-inbox

- **适用场景**：截图/图片文字提取并入库知识层。
- **触发方式**：「读一下这张截图 / 把屏幕内容记下来」。
- **边界**：capture_screen 或 read_file 取图；不确定字符标「□」；knowledge_save 入库。

## release-notes

- **适用场景**：发布说明、更新日志、版本公告。
- **触发方式**：「写 release notes / 更新日志」。
- **边界**：Added/Changed/Fixed/Removed 分组；破坏性变更置顶附迁移说明。

## api-doc

- **适用场景**：接口/RPC/SDK 参考文档。
- **触发方式**：「写 API 文档 / 接口文档」。
- **边界**：以实现为准取证；示例与参数表自洽；文档与实现差异显式标注。

## refactor-plan

- **适用场景**：结构性重构的先计划后执行。
- **触发方式**：「重构 XX / 出重构方案」。
- **边界**：每步可独立验证；先补测试再动结构；发现隐藏耦合即停并修订计划。

## bug-reproducer

- **适用场景**：模糊 bug 报告的复现与定位。
- **触发方式**：「帮我定位这个 bug / 复现一下」。
- **边界**：最小复现优先自动化；二分定位留证据；无法复现不猜改。

## dependency-audit

- **适用场景**：依赖盘点、升级评估、许可证检查。
- **触发方式**：「审计依赖 / 能不能升级 X」。
- **边界**：升级建议附验证方式；许可证风险单独标注；漏洞公告注明来源。

## test-plan-writer

- **适用场景**：需求/变更的测试计划。
- **触发方式**：「出测试计划 / 测试用例」。
- **边界**：正向+边界+异常分组；覆盖缺口显式声明；优先增量补齐。

## competitive-scan

- **适用场景**：竞品调研与对比。
- **触发方式**：「对比一下 XX 和 YY / 竞品动态」。
- **边界**：deep-research 纪律；对比表逐格给来源；事实与推断分节。

## fact-dossier

- **适用场景**：零散事实核验后沉淀事实层。
- **触发方式**：「把这个记下来 / 建档」。
- **边界**：一条一义带来源与置信度；冲突提示用户裁决；fact_save 落库。

## xlsx-analysis

- **适用场景**：既有表格的统计分析与结论提炼。
- **触发方式**：「分析这张表 / 这批数据说明什么」。
- **边界**：先述数据形状；口径歧义先问；估算说明方法。

## slide-outline

- **适用场景**：演讲/汇报的结构设计。
- **触发方式**：「帮我理个演讲大纲 / 怎么讲这个主题」。
- **边界**：先确认听众/时长/记忆点；时间预算到页；可续接 pptx-deck。

## changelog-curate

- **适用场景**：散乱提交/工作记录整理为分组日志。
- **触发方式**：「整理变更日志 / 把这些提交归归类」。
- **边界**：同主题聚合；沿用既有 CHANGELOG 风格；待归类条目请用户裁决。

## localization-pass

- **适用场景**：界面文案与文档的中文表达与术语一致性检查。
- **触发方式**：「检查翻译 / 文案优化」。
- **边界**：术语一致性优先；分级改写；占位符原样保留；确认后可批量应用。

## session-retro

- **适用场景**：工作会话复盘与经验沉淀。
- **触发方式**：「复盘一下 / 总结这次的经验」。
- **边界**：沉淀分三层（记忆规则/技能封装/一次性结论）；每条带证据与预期收益。
