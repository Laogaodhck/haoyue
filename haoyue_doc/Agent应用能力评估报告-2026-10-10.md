- 评估基准：「Agent 应用」形态的通用能力要求（自主循环、工具生态、记忆与上下文、规划与纠偏、多代理、人机协同、可靠性、安全、可观测、可嵌入）

## 一、结论摘要

**haoyue 已达到 Agent 应用的合格线，且在「元认知/自我改进」维度超出业界一般基线**；核心循环、工具生态、记忆、规划纠偏、事件溯源、回合回滚等骨干能力齐备并有测试护栏。主要欠缺集中在四块：

1. **工具执行的运行时强制权限闸门**（现为提示层约束，非强制层）
2. **子代理仅一层且串行**，无并行编排与后台长任务
3. **知识检索为纯词法**，无语义向量检索，长期记忆缺分层
4. **缺 Agent 级端到端评测**（现有 benchmark 评的是本地模型基础能力）

### 欠缺项

**G1 工具执行权限闸门（最重要）**  
`HaoyueRuntime.cs:198` 的 permission contribution 自述是「告诉模型它有什么权限」——即提示层约束；技能白名单（`SkillToolPolicy`）也只在注入层收窄工具视图。**没有任何运行时强制点**：Auto 模式下 bash 等变更工具一旦被模型调用即直接执行，没有交互式确认、allowlist/denylist 匹配或危险命令模式拦截。安全兜底只剩「事后 undo」，而 undo 不覆盖 bash 副作用（进程、网络、非受管文件）。

**G2 子代理能力单薄**  
`AgentDelegator.cs` 明确注释 "delegation is exactly one level deep" 且 "no parallel delegation"：一层、串行、无结果聚合策略、无角色化子代理（不同工具集/提示的专家分工）、无并行 fan-out。复杂任务的拆解-并行-汇合能力缺失。

**G3 后台长任务缺位**  
ScheduleService 覆盖了定时触发，但回合本身是同步阻塞的：没有「任务转后台继续跑、前端可断开重连」的机制，长任务占用会话。

**G4 检索与记忆缺语义层**  
知识库检索是同义词扩展 + CJK 二元分词 + 编辑距离的**词法**方案；无 embedding 向量检索，跨会话的语义记忆召回（「我们之前讨论过的类似方案」）做不到。记忆只有 MEMORY.md 单层，无用户画像/项目记忆/情景记忆分层。

**G5 无 Agent 级端到端评测**  
`benchmarks/local-model-eval` 评的是流畅性/速度/自修正/视觉——模型能力而非 **Agent 任务成功率**。没有可回归的任务集（类似 SWE-bench 式的固定任务 + 自动判分），纠偏策略（nudge 阈值、步数预算）的调参只能靠手感。

**G6 bash 无沙箱**  
BashTool 直接执行命令，无进程级沙箱、网络隔离或命令审计日志（事件总线记录了调用，但无前置风险评估）。

**G7 多模态只进不出**  
输入侧视觉（图片、截图核验）完备；输出侧无图像/文件产物生成，多模态应用场景覆盖一半。

## 三、改进建议（按优先级）

| 优先级 | 建议                | 对应缺口  | 要点                                                                                                                      |
| --- | ----------------- | ----- | ----------------------------------------------------------------------------------------------------------------------- |
| P0  | 工具执行强制权限闸门        | G1/G6 | ToolRegistry 执行前插入策略层：按模式 + 工具 + 参数正则匹配 allow/deny/ask；Auto 模式下 bash 高危模式（`rm -rf`、`format`、外发数据）强制拦截或转人工确认；配合现有事件总线落审计 |
| P1  | 并行子代理 + 结果聚合      | G2    | 解除一层限制改为可配深度；只读子代理并行 fan-out（复用 readOnlyBatch 的 WhenAll 模式）；引入角色化子代理（researcher/implementer/reviewer）预设                 |
| P1  | 后台任务队列            | G3    | 回合可转入后台执行，daemon 侧维护任务表，前端断线重连后经 `events.recent` 重放进度（事件溯源已具备，只缺任务编排壳）                                                  |
| P1  | 语义检索层             | G4    | 本地 embedding（GGUF embedding 模型或 ONNX）+ 混合排序（词法候选 → 语义重排），与现有高容错检索融合而非替换                                                 |
| P2  | Agent 级评测 harness | G5    | 固定任务集（10-20 个典型任务）+ 自动判分（文件断言/构建通过），每次改 nudge 阈值/提示词后回归，接入现有 coverage 护栏测试模式                                            |
| P2  | 记忆分层              | G4    | MEMORY.md 之上加自动沉淀的项目事实层（来源、置信度、过期策略），复用知识库存储                                                                            |
| P3  | headless SDK      | —     | 契约已单源导出，补一个 TS 客户端 SDK 封装 daemon 契约，降低第三方嵌入成本                                                                           |
| P3  | 多模态输出             | G7    | 图表/图片产物生成接入工具层即可，架构无需变动                                                                                                 |

## 四、总评

以 Agent 应用标准衡量：**循环与工具（满分）、纠偏与可靠（优）、协同与治理（中上）、安全强制（中）、多代理与后台（弱）、评测（缺）**。进化引擎使 haoyue 在「Agent 自我改进」这一维度上是同类项目中的少有实现，值得作为宣传主打；当前最值得投入的是 P0 权限闸门——它同时补齐安全短板，且是实现成本最低、收益最确定的一项（在 ToolRegistry 执行路径上加一层策略即可，不动 Agent 主循环）。
