# 跨语言契约治理（Contract First 落地）

- 日期：2026-10-07
- 范围：haoyue 全仓库（.NET / Electron-TS / Python）
- 状态：已实施

## 1. 问题

项目混用 .NET、Electron-TS、Python 多技术栈，跨语言边界缺乏单一事实源：

| 风险点 | 证据（实施前） |
| --- | --- |
| 60+ RPC 方法无单一事实源 | 方法清单在 `ProtocolInfoJson()` 手工维护，与 switch 分发人肉同步；`agent.undo`、`session.truncate`、`session.fork`、`config.save` 已实现但**未出现在对外清单**（漂移实锤） |
| TS 手抄 C# 结构，三处重复 | `shared/ipc.ts`、`renderer/types.ts`、`app-helpers.ts` 各一份；`RuntimeWorkspace` 缺 `projectKinds` 字段（静默漂移已发生） |
| 错误通道靠自由文本当契约 | error 事件无错误码，中英文文案混排，TS 测试把 `'请求超时'` 等文案钉死成契约 |
| 版本链路双正则 | `version.py:40` 与 `publish_npm.py:291` 各自解析 `Banner.cs`，格式一变双双静默失效 |
| 请求入口零类型约束 | `request(method: string, params: Record<string, unknown>)`，方法名/参数无编译期检查 |

## 2. 方案：haoyue_runtime 是唯一契约源（翻译器）

```
DaemonContract.cs（唯一事实源）
    │  方法目录 / 错误码 / 事件名 / 信封 schema（JSON Schema 2020-12）
    ▼
DaemonServer.contract.export RPC ──► 契约快照 contracts/daemon-contract.json
    │                                    │
    ▼                                    ▼
protocol.info.methods（派生）    scripts/generate-contract.mjs
（双清单问题根治）                        │
                                         ▼
                          src/shared/daemon-contract.gen.ts（生成，禁手改）
                                         │
                                         ▼
                          ipc.ts / daemon-client.ts（消费：事件名、错误码、DaemonError）
```

Python 侧：`publish_npm.py` 删除自带正则，`from version import read_file_version` 复用唯一实现。

## 3. 契约内容

### 3.1 错误码（error 事件 `details.code`，camelCase wire 值）

| code | 语义 |
| --- | --- |
| `requestFailed` | 未分类失败（兜底） |
| `invalidRequest` | 请求行非合法 JSON / id-method 类型错误 |
| `unknownMethod` | 方法不在契约目录 |
| `invalidParams` | 参数缺失、类型或取值非法 |
| `notFound` | 目标资源不存在 |
| `conflict` | 状态冲突（如会话已有活动回合） |
| `unauthorized` | 握手 token 缺失或不匹配 |
| `internalError` | 服务端未预期异常 |

规则：**每个 error 事件必须携带 code**（`WriteAsync` 自动补默认，调用方显式传精确码）；`data` 文本仅供展示，**消费方禁止对 message 做字符串匹配**。TS 侧异常为 `DaemonError`（`code` 缺失时回退 `unknown`，兼容旧版 daemon）。

### 3.2 方法目录

86 个方法，每个条目：`name / category / description / schemaStatus / terminalEvents / params? / result?`。

- **schema 全覆盖（86/86 specified，pending=0）**：所有 params schema 均逐一对照 `DaemonAdminApi.cs` / `DaemonServer.cs` 实际 `params[...]` 读取核实后建模；无参方法显式声明空对象 schema。
- 新增护栏测试 `Contract_AllMethods_HaveParamsSchema`：任何新增方法若未声明 params schema，测试直接失败——pending 状态从机制上不允许再出现。
- 通用选择器 schema 构件：`SessionRef`（workspace/global）、`KnowledgeScope`、`SessionExt`/`Scope`（克隆基础选择器并追加逐方法字段，自动合并 required）。

### 3.3 快照同步链（CI 可用）

| 步骤 | 命令 |
| --- | --- |
| 更新 C# 契约快照 | `HAOYUE_UPDATE_CONTRACT=1 dotnet test haoyue_tests --filter Contract_Export_MatchesSnapshot` |
| 契约漂移检测（默认断言一致） | `dotnet test haoyue_tests --filter Contract_Export_MatchesSnapshot` |
| 重新生成 TS 类型 | `cd haoyue_desktop && pnpm sync:contract` |
| TS 侧契约一致性测试 | `cd haoyue_desktop && pnpm test`（daemon-contract.test.ts） |

TS 契约测试双向校验：错误码、事件名（stream/terminal/broadcast）、方法清单与快照逐项一致；`TERMINAL_EVENTS` 与契约 terminal 事件一致；`errorCodeOf`/`DaemonError` 行为。

## 5. 后续演进（按此模式增量推进）

1. **TS 请求入口类型化**：`daemon.request(method, params)` 逐步迁移到 `DaemonMethod` + 生成参数类型，最终将 `method: string` 收紧为 `DaemonMethod`。
2. **渲染层手写类型归一**：`renderer/types.ts`、`app-helpers.ts` 中的 daemon 结构逐步改为从生成类型扩展。
3. **publish_npm.py / CI 消费 build-manifest.json**：发布脚本读取清单取产物，彻底移除对 publish 目录文件名模式的依赖。
